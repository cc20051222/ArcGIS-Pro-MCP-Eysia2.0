# ArcGIS-Pro-MCP 2.0 配套 Skill：设计、使用与验收

版本：0.7.1｜2026-10-19｜需求资料与成果位置确认、缺口清单、工具替代优先和当前步骤高亮完成自测。PASS CANDIDATE；前版独立验收不代签本版；旧段落按历史读取，当前交付见末节。

当前改进与证据边界见[0.7.1更新说明](../Docs/SKILL_071_RELEASE_NOTES.md)，旧版本段落仅作历史。

## 1. 定位与设计结论

暂停 3.0 规划，本次只交付适配 **2.0 现有后端**的工作流 Skill。它负责让 AI 正确发现工具、理解数据、选择方法、执行已授权任务、检查成果及处理失败。MCP 提供执行能力，Skill 提供使用这些能力的可复用操作方法；Skill 文件本身不增加 GP、Photoshop 或宿主功能。

采用 **一个用户入口、按需场景参考（含水文、原生界面与三维科学核验）、一个离线能力快照、一个可选任务合同和本地辅助脚本**。不为每个工具建立一个 Skill，也不把 239 份工具 schema 塞入主提示词。简单查询可以直接完成；复杂任务才加载相关专业流程和恢复说明。

主入口：[arcgis-pro-2-workflows/SKILL.md](arcgis-pro-2-workflows/SKILL.md)。研究依据与取舍：[validation/research-sources.json](validation/research-sources.json)。初版离线验证：[validation/skill-validation-report.json](validation/skill-validation-report.json)。当前自测与整改见 D:/shiyanwenjaijia/自测记录/Skill自测与整改报告.md；0.4.0 的独立离线回执在该根目录的自测记录内。

## 2. 结合 2.0 实际能力，而非沿用旧计划

初版先复算注册表、契约、分类名册、错误码及白名单并生成来源哈希。0.4.0 已安装到本项目的 .agents/skills 并被本会话发现；按用户授权在已打开的 Pro 3.5 上通过既有回环 MCP 完成真实发现、只读查询、缓冲/擦除、相交复检、Shapefile 导出、布局整改及工程另存。未执行 Photoshop，也不代表全部 239 工具已验收。

|---|---:|---|
| 注册工具 / 契约名称 | 239 / 239，名称集合相同 | 作为离线定位依据，调用仍取当前 schema |
| 执行通道 | Native 156 / Geoprocessing 56 / Python 7 / Bridge 20 | 不等同于逐件运行验收 |
| 分类名册 | Read 94 / Session 33 / Write 158，共 285 | 包含未注册候选，不能宣传为 285 个生产工具 |

用户所说“2.0 已完成”保留为项目阶段背景；上述具体执行边界以本次源码观察为准。这些限制可能在以后版本解除，但需要对应新版本的能力与运行证据。本 Skill 不重写项目完结裁定，也不替代真实客户端及端到端验收。

## 5. 使用者操作流程与明显区别

普通用户示例：“给这批学校做 500 米服务范围，统计覆盖人口，再输出带图例、指北针、比例尺的 A3 地图，放到 D 盘指定目录。”

AI 应先只读识别学校与人口数据，检查坐标系、单位、时间、统计口径和同名对象。这里“服务范围”可能指距离缓冲，也可能指沿道路可达范围；如果上下文无法确定，集中询问方法及真正缺失的业务信息。确定后给出精确输出路径与对应操作，沿用已有明确授权，在受控工具支持范围内执行并检查成果。没有网络数据或许可时，不能把缓冲圈称作路网服务区。

用户能感知的区别：

- 不必背工具名和参数；AI 解释业务选择，并且不虚构后端参数。
- 先认清是哪份数据、哪个选择集，再计算，避免“做出来但用错对象”。
- 输出位置、已有资产覆盖与就地修改清楚，已经授权的范围不用反复确认。
- 制图交付包含实际预览检查；无法预览则如实标记，不凭成功响应说“美观合格”。
- 失败时给出已完成成员、未完成成员与可安全继续的位置，避免整批重做。
- PS 没有真实运行支持时提前说明，普通用户不被迫学 PS 后再被计作“自动化成功”。

支持三种自然操作方式，不要求切换设置：只读咨询直接查；目标式制作由 AI 补全非关键步骤；专业用户指定方法、环境和精确输出时保留其选择，除非缺少必要条件或违反当前约束。

### 5.1 根据实际选择流程

选择流程依据六方面：业务目标与成果用途；数据身份/范围/质量；CRS/单位/格网/统计等方法条件；真实工具实现/许可/宿主；工程现场与授权；输出规格与规模。先排除不正确、无授权或不可执行的方案，再在等质量选项中减少重复读取、调用和等待。不能单凭工具少、关键词分高就称最优。

`suggest_workflow` 当前只是冻结六场景关键词匹配，提供候选和缺失输入，不是通用优化器。Agent 应结合专业参考调整、组合或省略步骤。`apply_processing_plan` 也不是通用 DAG 引擎；当前注入 target 不等于自动替换每个工具的 input/output，跨步绑定和唯一输出需实查，必要时逐项调用。

用户更改目标或数据/环境发生变化时，创建下一计划版本，解释变化与影响，保留已有成果；只重规划受影响的剩余步骤。旧成果失效时明确标记，不能沿用旧统计去冒称新方法。原授权范围内继续执行，新增覆盖、外传或方法/数据范围改变才补充相应确认。

### 5.2 使用时能看到什么

默认在**当前聊天**中展示，不要求用户另装面板或开启服务器：

1. 开始前看到简短流程卡：目标、对象与范围、方法依据、步骤/依赖、输出位置与缺口；支持的客户端可加 Mermaid，文字表始终保留。
2. 执行时看到当前步骤和最近观测时间；重要返回/产物/失败/方案变化即时更新，能够响应的长任务约 30–60 秒给一次有意义状态。单次阻塞调用期间可能无法发消息，不做固定刷新保证。
3. 看到真实后端计数与质量核验数量分别呈现，如“执行成功 9/10，失败 1；成果已核验 7/10”。未知总数显示未知，不用时间动画或步骤占比冒充实际耗时进度。
4. 关键节点看到真实地图图像、布局试页、小样本表格和已生成文件链接；预览、正式、旧版本、待核验分别标清。地图视图回图不证明纸面图例和标题已正确排版。
5. 受阻时看到具体原因、已完成成员、影响与可继续位置；用户可随时要求更简洁、更详细、暂停、取消或修改目标。取消请求和实际停止分开。

现有 2.0 提供 get_job_status/get_job_report 查询，以及 export_map_view 原生图像回传的源码接口。此版 Skill 使用这些已有能力，但**未验证真实客户端展示效果**。MCP 协议支持可选进度通知，不等于本产品和客户端已经实现；本次检索未取得 notifications/progress 推送实现证据。无 jobId 的同步工具显示“等待返回，内部进度未知”；轮询不能推进分片，不能盲目重发写操作。

详细规范：[场景适配与进度展示](arcgis-pro-2-workflows/references/adaptive-flow-and-progress.md)。[流程板模拟样例](validation/fixtures/task-board.synthetic.md) 使用显著的 SYNTHETIC_NOT_LIVE 标记；它演示状态组织，没有实际 GIS 结果。

### 5.3 如何实现和接入

Skill 主体控制 Agent 的选流程、解释、更新时机和核验行为；专业参考给出条件和分叉；可选任务记录保存步骤、依赖、计划版本、观测引用与成果。`render_task_board.py` 把记录格式化为 Mermaid、文字表和路径，检查依赖环、状态依据、计数和路径，但不证明记录中的执行事实，也不自动刷新客户端。

Agent 在每次真实事件后更新记录并重新生成展示，使用客户端已有消息/图像能力发布；没有 Python 时直接按同一规范发消息。当前不新建后端推送、Web 服务、GIS 工具或客户端配置。若未来需要独立的常驻可交互面板，应单列产品开发和客户端适配验收，不能把提示词当已完成的 UI 插件。

### 5.4 行业适配、复检与最终验收

以业务问题、数据类型、分析方法和成果用途组合流程，再按自然资源/规划、生态环境、应急交通、遥感、科研、测绘地形、专题制图、PS 素材或批量转换加入适用质量项。先保证方法与结果正确，再在等质量选项中优化效率。不能把同一个关键词模板用于所有行业，也不把当前没有真实实现的工具当作可用路径。

制作全过程为：**资料预检→方法/质量计划→执行与首次检查→新证据复检→问题修复及重检→最终交付检查→提交候选→有权角色验收**。简单任务可合并展示，但不能省略适用的检查。复检要重读实际成果，不复制首检报告；改动后只重检受影响项和最终交付一致性，旧证据保留并标失效。

每个质量要求明确判据、来源、对象版本及 FULL/SAMPLE_ALLOWED 范围；每条检查保留方法、覆盖数、总体数和实际观测引用。状态板分别展示四阶段检查、未关闭缺陷、验收状态与下一步。最终检查核原需求、数据/数值、完整成员、格式与实际可打开、地图真实视觉、版本/哈希、可领取路径及限制。文件完整性不能替代空间/统计/视觉正确性。

全部制作步骤与必需检查通过、严重问题关闭才形成 PASS CANDIDATE；制作端不自批最终 PASS。真实用户或有权独立验收方的当前版本裁定单独记录，未回复不算批准。若图中有外部验收节点，它不计入制作端的必需完成项，等待裁定的状态仍清楚可见。

行业符合性必须核实际采用版本、条款、阈值来源、检查方法及覆盖证据。本次只核了 GB/T 24356-2023 官方目录，以及 ISO 19157-1:2023、ISO 19115-1:2014 公开摘要，没有完整逐条标准实施或认证；不虚构精度/抽样率，不宣称所有行业通用合格。完整规则见 [质量、复检与最终验收](arcgis-pro-2-workflows/references/quality-and-acceptance.md)。

## 6. 权限与工作区规则

Skill 选择与调用不是写入授权。真实安装、客户端配置写入、GIS 写入、依赖安装、签名发布和干净机部署仍按本工作区规定取得具体授权；现有会话已经明确授权的内容继续有效。`confirm=true`、工具分类或 `readOnlyHint` 都不能替代用户授权。

项目输出、中转、scratch、显式审计和预览使用 D 盘；准备写入时在获准目录做可写检查。保持旧仓库、用户原件、fixture、未知锁、发布封存件和回滚链的保护。不生成绕过 MCP 路由的任意 ArcPy/JavaScript/HTTP 旁路，不关闭只读模式以强行执行，不为本 Skill 修改产品注册表、构建、安装或打包。

并发按资源决定：独立只读查询可在宿主允许时并行；同一工程、编辑会话、布局、输出和 PS 文档的写入按依赖串行。`run_batch` 是顺序分项执行，不是事务，也不是并行加速器。超时或取消后先查真实状态。

## 8. 规范、评测与验收
