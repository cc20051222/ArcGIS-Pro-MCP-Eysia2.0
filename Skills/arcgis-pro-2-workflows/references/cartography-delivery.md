# 专题制图、布局、地图册与导出

## 先定成果规格，再改工程

优先复用用户明确指定的地图和布局；未指定时只读枚举，确定地图框和数据源。告知要新建的拥有布局/输出，以及是否会改既有符号或标注。把标题、主题、研究区、页幅/横竖、语言、比例尺适用范围、输出格式与分辨率合并成少量确认；已有信息不重复问。

基于字段语义选符号：类别用区分类别的颜色，连续量用有序色带，正负偏差可用有意义的中点；总量与率不混同。`set_layer_renderer`、`set_simple_symbology`、`apply_symbology_from_layer` 只采用已支持参数；`set_label_properties` 核中文、字体、单位和溢出。需要统一改多图时先在一个拥有布局验证，不一次覆盖全部用户布局。

## 正确的调用骨架

`list_maps` / `get_layers` → `list_layouts` / `get_layout_info` → 规划 → 已授权符号/布局动作 → `list_layout_elements` / `get_layout_info` → 正式导出 → 真实打开/渲染检查。

当前 `create_layout` 使用 `pageWidth` / `pageHeight` / `pageUnits`，可绑定 `mapName` 与地图框范围；**没有 dpi 参数**。DPI 在 `export_layout_pdf/png/jpg/tif/svg/eps` 的 `resolution` 参数中，不能照抄其他 API 的 `dpi`。当前导出 schema 默认 SDK 96 DPI；用户要求 300 DPI 时显式 `resolution=300`，不能把 UI 显示或文件名当输出分辨率证据。

过程展示按 [场景适配与进度展示](adaptive-flow-and-progress.md) 选择关键预览点。`export_map_view` 返回的地图图像不包含纸面布局，不证明图例/标题已合格；布局使用真实试页。地图回图的 `resolutionDpi` 与布局导出的 `resolution` 是不同参数。只显示真实版本与核验状态，不为了“实时”反复导出、切换用户活动地图或覆盖旧图。

按目标使用 `add_layout_text`、`add_legend`、`add_north_arrow`、`add_scale_bar`、`set_layout_element_properties`。图例条目、单位、比例尺和指北针应绑定真实地图框与地图语义。布局元素修改可能就地发生，不能承诺元素级自动回滚；新建布局撞名时按当前契约处理，不静默选现有布局或改名。

地图册需先核页索引、分页字段、排序/范围与地图系列配置，再用 `configure_map_series` / `export_map_series`。返回条数、页码/缺页与实际文件对应，局部导出不能声称全册。

## 可见检查与完整性

- 必需元素：标题/图例/指北针/比例尺、单位、数据/时相/方法来源；用户明确要求的要素逐项检查。专题本身不适用某元素时解释适用性，不能静默漏掉。
- 版面：中文正常、字号可读、标注/图例不截断、不遮挡关键对象、颜色可区分、比例尺尺寸与地图框一致。数学/统计结论来自数据，不从漂亮图像推断。
- 产物：格式与扩展名、页数/像素、分辨率、文件大小/可打开、是否覆盖、精确输出路径。Shapefile 按实际必需侧车件检查，GDB 检查内部数据集而非只看目录。
- PDF/PNG/TIFF 等尽可能在当前可用查看器中实际打开或渲染；没有查看工具时准确写“已导出、视觉未核验”，不能宣称无截字或达印刷质量。

印刷 ICC、色彩管理或可访问性有具体要求而当前工具未提供必要检查时单列未验证项，不冒称 PDF/UA、无障碍或印刷标准认证。导出 GIS 图片不等于完成 PS 自动美化。

## 首检发现问题后的真实复检

GP 自动加入的中间层、导出层或重复结果可能盖住已经设置的符号，也可能污染图例。正式布局前读回实际图层和顺序，仅移除本任务明确创建的多余引用，保留对应数据和质量证据；随后重读并重新查看地图。图例须覆盖全部承诺主题且与真实颜色一致，不能以元素已存在代替内容检查。

元素创建的 x/y 不一定是最终读回的锚点坐标。移动或调整后通过 list_layout_elements 和真实导出检查边界、碰撞与页外溢出；首检、修复、复检分别留证，最终文件再检像素和 PNG pHYs/DPI。set_map_extent 的返回可能写 CustomFullExtent 而读回 default-extent，sameSource=false 时不能声称活动相机已缩放到请求范围。必须看真实地图/布局是否完整，不虚构相机控制参数。

二维+三维同幅、相同地理范围和真实三维阴影是不同要求；用二维图复制成两个地图框或拉伸示意图不能满足它们。无法制作必要三维成员时，二维成果只作部分交付，整单保持受阻。

本机组合实验补充：`create_layout`一次只能绑定一个地图框；现有接口没有通用新增第二框/克隆元素参数。用户已授权原生界面时，可在自有中间布局复制真正Scene地图框到正式布局，随后核两框地图URI、Scene类型、页面位置与最终渲染。复制图层的剪贴板对象不是地图框，必须重新确认对象类型。

`add_scale_bar`默认可能是英里。检查真实CIM单位与导出标注，需要米时通过已支持入口或经授权的原生属性页改单位，不能只把英里文字改成“米”。激活布局地图框后，活动MapView可能就是该框；先读回mapName再操作。`set_map_view`范围缩放和原生全图命令在本机Scene会恢复默认heading，缩放后重新核相机；必要时使用原生朝北与投影坐标平移，最后读回两框四至和heading逐值比较。透视pitch与二维俯视不同，应明确表达同一地面范围，不能用相同标题冒充范围相同。

本机多面体`set_simple_symbology`曾返回成功但颜色读回为空；不据此宣称多面体着色完成。可在真实Scene显示经高度核验的着色拉伸面，同时保留分析多面体；仍须检查实际图像。详见[原生界面与三维科学核验](native-ui-and-3d.md)。
