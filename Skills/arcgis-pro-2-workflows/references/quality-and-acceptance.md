# 场景质量合同、复检与最终验收

用于制作与交付任务。先选适合场景的方法，再把“做得对、完整、可用”的条件写成检查项。普通只读查询只检查答复依据，不强制建立生产批次或等待外部验收。Skill 不替代测绘单位的质量责任、资质、合同要求和有权验收方。

## 1. 行业要求如何落地

依据优先级：适用的有效标准/技术设计书/合同与用户明确成果要求→本项目硬约束→明确说明的通用专业实践。发生冲突说明具体差异，不自行决定标准适用性或降低质量。标准编号、版本、适用对象、采用条款、检查方法、阈值及来源都要可追溯。

本次核查的官方资料包括 GB/T 24356-2023《测绘成果质量检查与验收》现行目录记录，以及 ISO 19157-1:2023 数据质量和 ISO 19115-1:2014 元数据的公开摘要。**未取得并逐条解析完整标准文本，不能声称完整落实其条款。** 国家/地方/行业专业项目先确认实际采用版本与技术设计书，形成条款映射后才能给出相应符合性结论。标准元数据/摘要可用于确定研究方向，不提供现成精度、抽样率或允许缺陷数量。

通用要求包括：对象和来源正确，范围完整，CRS/单位/时相可追溯，方法成立，属性/几何/格网/统计一致，输出可用，地图表达忠于事实，失败与未知不隐瞒。精度、面积差、拓扑容差、统计置信度、抽样数量等取自明确的规格与适用依据，不通用设置“95%合格”或套用任意 epsilon。用户无需理解标准号，Agent 解释影响结果的业务选择与真实缺口即可。

## 2. 组合场景与质量要求

不是为每个行业写死一条流程。采用“业务问题＋数据类型＋处理方法＋交付用途＋行业覆盖项”组合，对同一目标按现场分叉。

| 场景覆盖项 | 在专业工作流上增加的检查 | 不能自动推断 |
|---|---|---|
| 自然资源/用地与地块 | 分类编码/依据版本、面积单位、拓扑、重叠与汇总分母 | 法定边界、权属结论、统一面积容差 |
| 城市规划/设施服务 | 指标含义、直线/路网方法、人口时相/分配、规划范围与统计一致 | 距离缓冲等同实际服务可达，或图形等同审批成果 |
| 生态/环境评价 | 指标单位、掩膜/空间尺度、时间可比、阈值来源及敏感性 | 美化后颜色变化代表真实环境变化 |
| 应急/交通与路网 | 事件时间、来源更新、道路连通/阻断、行驶模式和许可 | 旧数据可支撑实时安全调度 |
| 遥感/土地覆盖 | 波段角色、格网/NoData、独立参照、分类编码与混淆矩阵分母 | 更细重采样提高真实精度，或训练样本就是独立验证 |
| 科研与空间统计 | 样本/权重/尺度、检验前提、泄漏、显著性与多重比较、可复现参数 | 相关显著等同因果，数组算法覆盖完整专业工具箱 |
| 测绘/地形与工程 | CRS/高程基准、精度与容差依据、检查点/范围、专业技术设计书 | 仅有 CRS 就满足测量精度或工程安全要求 |
| 专题图/地图册 | 数据来源、分类色义、图例/指北针/比例尺绑定、中文、页序与正式规格 | 地图视图截图证明纸面布局合格，文件哈希证明空间正确 |
| 设计素材/PS | GIS 科学区与事实、素材版本/锚点、真实对端执行、保存重开与完整成员 | 注册 ps 名称或素材包检查成功就等于 PS 已完成 |
| 通用批量转换/清洗 | 逐成员映射、字段/编码/几何损失、完整性、原件保护与异常清单 | 扫描首批为全量、转换成功为无损、同参数适配异构文件 |

输入充分、许可可用且判据可检查才进入执行。缺少特定行业规格时可先完成获准的资料检查、通用分析或明确标为草案的成果；不能把它当正式行业验收品。

## 3. 全过程阶段与可视化

| 阶段 | 必须呈现的事实 | 进入下一阶段的依据 |
|---|---|---|
| 需求/资料预检 PREFLIGHT | 目标/对象/范围、方法缺口、许可、输出与保护对象 | 必要条件成立；方法与授权缺口已解决 |
| 方法/质量计划 | 适用质量项、阈值来源、全检/抽样范围、依赖与产物 | 质量标准和场景一致，不为方便而降级 |
| 规范执行与首次检查 PROCESS | 当前步骤、原始业务结果、数量/单位、阶段预览、已知缺陷 | 各步有真实成果/状态及初查记录 |
| 复检 RECHECK | 实际重读/重测、问题修复证据、覆盖范围与剩余缺陷 | 必需复检通过，未用旧报告代替新证据 |
| 最终交付检查 FINAL | 逐需求/逐必需成员核对、最终版本、真实可打开/视觉、交付限制 | 全部必需检查通过且严重问题关闭，形成候选 |
| 外部验收 | 候选、待审/拒收/已验收、验收人角色/记录与版本 | 用户或有权独立验收方的明确裁定 |

展示沿用场景流程卡，并附质量阶段表、检查覆盖和缺陷清单。文字状态和图像并用，不只依赖颜色；无证据的节点标待检查、未知或受阻。执行成功项、已核验成果、复检进度、最终验收状态分别统计，禁止合成一个假的完成率。

用户将“过程中可观看”列为需求时，增加独立展示检查：首次业务执行前已在聊天显示流程/表、执行中关键节点有直接可见更新、有真实预览时直接展示、阻断/复检/最终检查均已显示。引用具体消息或客户端观察；本地看板存在、程序测试通过和制作 Agent 的“已显示”声明不替代渠道证据。用户反馈没看到则记录该项未通过，不能在报告中保留“实时可视化已完成”。补发历史图只能补充归档可读性，原生产过程的观看缺口保留；修正规则后的完整制作周期展示需另行实测，不自动重跑 GIS。

## 4. 首检、复检与修复闭环

首次检查随步骤执行，核实际效果，而非只检查 HTTP 成功。复检必须重新读取最终数据/文件，采用适合该判据的检查，形成新的 observation。可以使用相同算法复测数值，但必须是新测量；关键结论宜加入不同视角的核对，例如数据集数量/汇总与报表对账、布局元素与最终渲染核对、清单与实际文件枚举对账。复检不等于另一个模型重复阅读制作摘要。

缺陷记录包含位置/对象、判据、级别、影响、状态和证据。CRITICAL（空间/单位/方法严重错误、原件受损、越权、伪造成功等）和 MAJOR（必需成员或关键质量项不满足）未解决时不形成合格候选。MINOR 也要披露；保留项只有获得验收方明确接受及记录，才可按其授权范围处理，不能暗中降低必需标准。

修复前核对应写入授权；默认新版本保留旧件。修复后重测原问题及受影响依赖，更新数据/方法/产物版本，旧检查失效。关闭缺陷需要实际修复/复检证据，仅改状态、重命名、复制报告或重新计算文件哈希不等于问题解决。用户后续编辑同样触发相应复检。

大数据检查区分 FULL 与 SAMPLE，记录总体数、实际检查数和样本设计。全检要求不能用抽样通过代替；全量无法检查就标不足并报告影响。抽样允许时按适用依据选样，覆盖高风险、极值、边界、缺失及随机样本；不发明通用抽样率。空数据是否可交付取决于目标，不能因 0 个错误就推导业务满足。

## 5. 最终检查清单与工具边界

最终检查至少对照原始目标逐项核：交付对象与统计范围；方法/许可/环境；数据数量、字段、CRS/单位与关键数值；完整成员与组合格式；真实文件内容与可打开；地图页幅/页序/分辨率/必要元素和真实视觉；版本/来源/检查范围/未验证项；缺陷闭环；精确路径及用户可领取成员。承诺 PS 成果时单独核真实 PS 执行与保存重开，不能以 GIS 图片抵扣。

按当前 schema 使用已有质量工具，但限定它们的证据范围：

- `generate_quality_report`、`validate_geometries`、`validate_field_constraints`、`check_topology_rules`、`compare_datasets` 等需要真实服务、规则与范围；读取 maxFeatures/截断及实际检查数。生成报告不证明全部检查通过。
- `inspect_raster_alignment` 只支持其实际可观察的对齐事实；仍需波段、NoData、值域和业务质量检查。
- `validate_delivery_package` 检查清单、文件及字节/哈希，不证明空间分析、统计或视觉正确。
- `validate_design_bundle` 可返回 valid_with_limitations；字体/ICC/某些尺寸与锚点可能未完整验证，不能以 valid=true 覆盖这些限制。
- `validate_interchange_conformance` 当前结构检查不含完整声明标准规则库，返回 conformanceClaim NOT VERIFIED；不能据此宣布行业符合性。

2026-10-18 0.5.1 实机整改：本机 Pro 3.5 已启用修复构件，`validate_geometries` 和 `check_topology_rules` 不再是原占位；旧包仍可能返回 NOT_IMPLEMENTED，需按现场版本判断，不因工具可发现便推断已修复。其它质量/溯源接口的占位不因此解除。

几何检查支持 null_geometry、self_intersection、short_segment、duplicate_vertex。未传 checks 时四项均请求，但 minimumSegmentLength 缺省 0 表示短边检查禁用，不能算四项全部应用。先确定业务阈值；仅做数值健康检查时，可读数据集 XYTolerance 并明确作为数值阈值，不把它宣称为测绘或业务精度。maxFeatures 缺省 1000，读 totalFeatureCount/scannedCount/countBasis/truncated；全检时明确给足上限（最高 1,000,000）。点/多点没有短边，为 NOT_APPLICABLE。重复顶点按部件内精确 XY 计数，闭合必需末顶点不算重复；短边用真实 SDK 段长与 CRS 单位，不自动换单位。

拓扑只接受下列规则，禁止把“六类已实现”说成全部 Esri 拓扑规则或行业认证：

| rules 成员 | 适用范围与判据 |
|---|---|
| must_not_overlap | 面/线跨要素同维内交；包含、重复也违规，单纯边界接触或线点式交叉不算重叠 |
| must_not_have_gaps | 面并集内部孔洞；不验证未提供业务边界的外围覆盖完整性 |
| must_not_self_intersect | 线内部交叉/回描，允许合法自接触；含已有顶点上的 X 穿越检测。面依赖强制 OGC 检查，非自交的首个无效原因不能被冒称自交 |
| must_be_single_part | 线按路径、面按外壳；面内孔不误算为另一个外部件 |
| must_not_self_overlap | 线实际 SDK 线/曲段间的一维重叠；无法排除的单曲线内部回描返回未完成 |
| must_not_have_dangles | 开放线路径端点连接其它段（允许同要素非自身入射段）；闭合路径豁免；不自动修复合理道路尽头 |

拓扑读取底层整个要素类，不使用地图选择和定义查询，不创建/修改地理数据库拓扑对象。上限 10,000 要素、2,000,000 次成对工作预算，超过/耗尽不能返回完整通过。clusterTolerance 的非零值仅支持投影 CRS 下悬挂连接距离；其它规则拒绝非零值，避免忽略用户阈值。0 使用数据集 XYTolerance；不执行吸附、聚类或改写输入。这与带聚类/例外管理的地理数据库完整拓扑验证是不同范围。

每次分别检查 MCP 执行错误与业务 qualityVerdict。FAIL 是检出实际缺陷；INCOMPLETE 表示抽样、预算、SDK 能力或规则未能完整评估；NO_FEATURES 不能作正常成果通过；PASS_WITH_LIMITATIONS 包含禁用检查。读取 coverageComplete、allRequestedChecksApplied、逐规则 status、unassessed 和截断字段。证据最多 500 条，总发现数仍保留。非简单单曲线、复杂曲线节点或 SDK 首因不能分类时不发无依据 PASS；本次真实曲线、旧版 API 缺失与预算耗尽案例尚未实际取证。

本轮真实验证：24 组数据含合法/缺陷/退化节点反例，36/36 项黑盒检查符合预期；原 20m/25m 输出各 6/6、新 3m 压力输出 10,000/10,000 完成四项几何全检。道路独立缓冲允许相互重叠，不为了“拓扑全过”强加禁止重叠或无缝覆盖规则；按实际需求选规则并披露未适用项。新输出额外通过无重叠检查。详细开发证据在项目 Docs/PROGRESS_PANEL.md；这些数据测试不自动等同于用户考试成果整套验收。

只读检查默认不带 reportPath；确需保存报告才用已获准的 D 盘新文件。复检与最终检查不自动修复或改写原件，也不启动新的安装/配置/公开发布。

## 6. 候选与验收的分离

全部必需检查通过、观测有效、检查范围符合要求、严重缺陷关闭后，制作 Agent 提交 **PASS CANDIDATE／待验收**，同时提供可复核的成果和检查记录。日常业务可由用户明确接受；本工作区维护任务仍遵守指挥席独立验收。自检全部通过、用户没回复或超时都不构成最终批准。

最终检查是 Agent 应执行的技术步骤，最终验收是有权角色的裁定；两者都必须显示。即使另一个 AI 做了复检，若没有独立验收授权和对应裁定，也不能自动改成已验收。拒收或目标变化后保留原记录，针对具体问题修复再提交，不重写过去的结论。

## 7. 记录合同与离线检查的边界

任务记录 schemaVersion 1.2 增加 quality：profile/profileRevision、boundPlanRevision、producerId、standardMappings、subjectVersions、requirements、checks、issues、history、acceptance。requirement 包含 id/title/criterion/source、required、phases（PREFLIGHT/PROCESS/RECHECK/FINAL）、subjectIds、coverageRequired（FULL/SAMPLE_ALLOWED）。这些是任务记录字段，不是新增 MCP 参数。

每项 check 包含 id、requirementId、phase、state、method、profileRevision、bindings（被检对象版本）、scope（mode/population/checked，抽样另给 sampleDesign）、evidenceRefs；PROCESS+RECHECK 同时适用时，复检还记录 recheckOf 指向首次检查。一个 requirement/phase 只保留一条现役检查，替换前把旧记录写入 history，避免挑选通过项隐藏失败。

离线格式化工具从 required 检查派生四阶段状态，不信任输入里的“gates=PASS”。缺失/未检查/未知/版本过期、全检不足、重复复检证据等不能合成为通过；空要求列表也不算通过。它只检查记录内部一致性，不测量 GIS 真值、不鉴定身份、不授予权限、不提供标准认证。

subjectVersions 用真实的数据/方法/布局/产物身份与版本；哈希只有实际计算过才能填。对象改动时更新受影响 subject，计划变动先核质量合同 boundPlanRevision，再复用未受影响证据；否则旧检查显示 STALE。验收记录必须指向同一份当前候选，使用 USER 或 INDEPENDENT_REVIEWER 角色及有据的 reviewerId/evidenceRefs；制作角色不得自批。
