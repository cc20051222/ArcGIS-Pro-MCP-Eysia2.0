# ArcGIS Pro MCP：自动设计与逐模块实现 V5

日期：2026-09-27。状态：**实现设计草案，尚未实施或LIVE验证**。

用户前提：不会使用PS，人工设计占比很少。默认体验必须由系统完成设计与修正；专家编辑可选。本文覆盖V4的设计/交互优先级，沿用其GIS、安全、公共执行入口、恢复和来源机制。拟议名称与schema需正式工单冻结，不是已存在API。

## 1. 最重要的架构变化

**DesignBrief＋DesignSpec＋已接受的DesignPatch是设计主事实源；PSD/PSB是可重新生成的执行产物。**

用户通过用途、自然语言或快捷动作修改上述结构，系统再编译为有限的布局/UXP动作。默认不从复杂PSD逆向猜测用户想法，也不依赖人工逐层编辑才能完成。

数据和分析仍由现有GIS工具承担；系统只对已批准任务范围编排动作。所有业务调用经唯一Registry/公共执行入口，不增加任意Python、JSX、raw batchPlay接口，不复用6511作PS旁路。

## 3. 自动设计内核：A01–A10

这些编号表示内部服务职责，不是新增MCP工具，不计入240工具总数。

### A01 · 成果需求解析与设计契约

**输入**：DesignBrief来自场景表单、已连接AI客户端或已保存项目配置。自然语言解析模型只提出候选结构；服务器验证类型与语义，不暗中再调用外部模型。

**拟字段**：purpose、audience、medium、pageSpec、requiredContent、styleProfileRef、outputSpec、allowedLayoutFamilies、mustPreserve、renderBudget。业务AnalysisPlan单独保存distanceModel、statisticsMethod等。

**实现**：
1. 从用途选择冻结默认值，显示哪些参数用了默认；关键信息不完整返回成组问题。
2. “清爽”“正式”“突出主题”映射到有限风格参数；没有定义的抽象要求先推荐解释，不伪装确定理解。
3. 将必需比例尺/北向/图例/出处与任务要求进入不可删约束，允许模板明确例外但不能为美观自动删掉。
4. 出图目录、允许新增文档/文件范围、预期规格和自动修正预算形成计划预览。

**验收**：相同输入/默认版本得到相同规范化Brief；样式修改不改变AnalysisPlan摘要；关键方法歧义必被识别；表单入口无需模型即可完成标准任务。

### A02 · 内容画像与模板匹配

**输入/输出**：DatasetContract＋FactTable＋DesignBrief → ContentProfile＋可用模板候选及淘汰原因。

**实现**：
1. 读取研究区边界长宽比、主副图数、类别数、图例标签长度、指标数量、标题/说明长度、空间分布和输出媒介。
2. 先过滤能力、许可、字体、输出规格不满足的模板；不能靠“看起来适合”忽略数据缺项。
3. 模板按用途/信息结构匹配；使用规则得分而非第一版训练模型。机构指定母版优先，但无可行布局时明确冲突。
4. 字体只能从已安装或有合法来源且已批准提供的清单选择；为可复现记录字体名称/版本或可获取标识。仅凭相同字体名不能断言渲染完全一致。

**输出状态**：feasible、missing_content、missing_font、unsupported_output、needs_clarification。它们是内部状态，外部错误映射仍复用既有体系。

**验收**：狭长/近方形研究区、1/多地图框、长中文/中英混排、类别很少/很多、缺统计值、字体不可得、未支持媒介。匹配不会删除内容以假装可用。

### A03 · 约束排版器

**输入/输出**：模板家族＋ContentProfile＋DesignSpec → LayoutSolution，包含页内元素/地图框位置、类型化尺寸、约束检查及候选差异。

**首版算法**：有限布局家族＋离散槽位搜索＋确定性测量。先实现可维护的规则求解器，待实际复杂度证明需要后才评估外部优化库。

**硬约束**：研究区/必需图层不丢；正文/图例满足模板最小字号；元素在页内；保护区不被非预期遮挡；图例类别与数据一致；比例尺/北向绑定正确；页数/尺寸在批准范围；内容依赖完备。

**软目标**：对齐、留白、层次、地图有效面积、文字密度、色彩协调与风格偏好。评分权重是版本化产品规则，并非客观美学真理。

**实现步骤**：
1. 使用物理页单位形成网格；从横/竖版、侧栏/底栏、多面板等获准布局家族枚举不超过12个结构候选。
2. 对文本做真实字体测量或目标渲染后的读回；估计仅用于早筛，不能用字符数量推算通过最终溢出检查。
3. 图例根据实际项高/列宽换列或换区域；不得把完整图例截掉。缩字号只能在已批准下限以上。
4. 先淘汰硬约束失败候选，再对剩余候选排序。extent变化、地图缩放与关联整饰由GIS服务重算，不直接拉伸地图栅格。
5. 页数不允许增加时，不自动生成附页；若可行域为空，返回原因和有限选项，例如选择已获准的大页版或减少可选说明。

**验收**：已知无解输入不得输出“最佳但不合格”成品；相同seed/版本结果稳定；计量单位转换和布局像素尺寸取整正确；读回验证实际渲染。

### A04 · 候选推荐与预算管理

默认生成少量候选，呈现1个推荐稿、最多2个可展开备选。用户可以直接接受推荐，不必参加每轮选稿。

**拟默认预算**：结构候选≤12、初始实际预览≤3、全作业自动修正≤2轮、总预览渲染≤5、最终高分辨率渲染≤2；同时受时间/内存/磁盘上限约束。所有上限共同生效，达到任一上限停止继续试错，实际数值在前置试验冻结。

**实现**：
1. 先用结构检查减少宿主渲染次数；需要PS效果评价的候选必须得到PS实际预览，原生草图明确标“布局预览”。
2. 选择硬约束通过的候选，按软分数和用户已保存偏好排序，保存推荐理由，如“长图例放右栏，主图可读面积更大”。
3. 预览带job/spec/candidate/revision，旧预览不替换最新请求；过期请求结果仅入历史。
4. 高分辨率仅用于最终选定方案和必要的有限修正，不对12个方案逐个渲染大PSD。
5. 用户主动换风格产生新修改任务和明确预算，不自动借此无限延长原任务。

**验收**：无合格候选、过期预览、预算耗尽、取消、低分辨率通过而高分辨率失败、PS排队、并发请求；记录实际次数防止无界自动循环。

### A05 · 自动质量检查器

检查对象是带revision的真实产物与读回数据，不只是模板配置。报告按三层给出pass/fail/unknown及证据：

| 层 | 检查内容 | 主要实现 |
|---|---|---|
| 科学与地理 | 坐标/单位/统计数值、分母、图例分类、地图比例/北向、完整范围 | FactTable、MapFrame签名、语义绑定、允许变换与已知答案 |
| 结构与可读性 | 字体可用、元素越界/遮挡、文字溢出、最小字号、图例完整、文件/母版可读 | 宿主测量/属性读回、页面几何、实际字体和文件检查 |
| 视觉表现 | 层级、配色协调、灰度与色觉可辨性、内容密度、留白、最终图面 | 确定性规则＋实际图像；可选模型建议；开发期专业盲评 |

只读检查工具仅检查已有产物；若检查过程需生成预览，必须作为明确写步骤执行并登记D盘输出，不能在read工具内偷偷写。

OCR/视觉模型不能单独证明文字准确、地图无错；显著性、地物和量化颜色以分析/渲染绑定为准。未实现的检查返回unknown；影响核心承诺的unknown阻止“已完整校验”结论。

最终格式逐项验证：PNG/TIFF实际尺寸和文件可读，PDF由支持的GIS输出链验证，PSD/PSB保存后重开。屏幕预览无法证明物理打印机色彩一致，印刷需明确色彩配置和校样范围。

### A06 · 有限自动修正器

输入是带证据的IssueSet，输出为白名单DesignPatch，不直接发送原始JS或actionJSON。

| 问题 | 可自动尝试的修正 | 不得采用的捷径 |
|---|---|---|
| 长标题溢出 | 换行、扩槽、调整布局、在允许范围内改字号 | 默默删标题含义或降至不可读字号 |
| 图例过长 | 调列/换槽/更大允许版式/已批准附页 | 删除类别、用省略号代替必需图例 |
| 文本与地图遮挡 | 移入可行槽位或换布局 | 覆盖必需地物、裁掉研究区 |
| 字体不可用 | 使用已批准同类型替代并重新测量 | 静默下载字体、假称原字体已嵌入 |
| 颜色不易分辨 | 在允许色系内调整，同步图例并重验 | 用PS全局滤镜改定量含义 |
| 比例尺/北向关联失效 | 返回GIS按当前地图框重新生成 | 直接画一个看似合理的比例尺 |
| 统计数值不一致 | 阻止交付，回查分析/事实绑定 | 修改数字使它“看起来一致” |

候选修正先通过M05范围检查；每轮重新跑受影响硬检查及规定的全局关键检查。记录改动、原因、前后revision。反复同一失败、结果退化、能力不足或预算耗尽即停止；不可通过自动降级验收标准获得成功。

技术上是一个有上限的状态机，不依赖多个AI互相评价形成无限循环。可选视觉建议仍转为同一个受限Patch，不能绕过验证。

### A07 · 自然语言/快捷操作修改编译器

**输入**：当前preview/spec revision＋用户意图＋目标语义元素；**输出**：DesignPatch或必要澄清。

示例草案（不是现有公开工具参数）：

```json
{
  "schemaVersion": "1.0",
  "baseDesignRevision": "design-r3",
  "intent": "make_title_more_prominent",
  "targetSemanticId": "page.title",
  "changes": [{"property": "typography.titleScale", "value": 1.12}],
  "scope": "presentation",
  "mustPreserve": ["analysisDigest", "classification", "mapFrameBindings"],
  "expectedOutputs": ["preview", "new-final-version"]
}
```

**实现**：
1. 常见指令映射到版本化有限词典和参数范围：简洁/正式/换色/字大/图例位置/横竖版/恢复上一版。
2. 自由语言由已有AI客户端提出Patch候选，服务器核target身份、参数、当前revision和语义。原始句子仅作日志摘要且避免敏感信息。
3. “只保留高风险区”可能是视觉强调也可能是数据过滤；只对不影响分析结论的确定解释自动执行，其余提出业务问题。
4. 修改标题不重算GP；修改页面尺寸重排并更新地图关联；修改分类/分析方法生成新的AnalysisPlan与批准范围。
5. 用户接受后把Patch写入设计意图历史，支持撤销/恢复；自由文本明确区分手写内容与自动指标绑定。

**验收**：至少20类常见改稿表达及同义说法；目标歧义、过期意见、越权改图、改色不改数、撤销、无模型快捷操作、中文与英文混排。

### A08 · 项目风格与批量一致性

用户明确保存后记录StyleProfile：字体层级、颜色、标识来源、布局偏好、目标媒介与适用项目。不要默认跨项目传播偏好。

**实现**：profile版本与模板解耦；项目配置覆盖默认值，但不覆盖科学硬约束；读取时检查字体/素材是否仍可用。批准的品牌色如果无法表现分类，要提出可区分的合法变体，不把不同类别画成无法辨认的同色。

批量任务固定断点/色阶/版式政策，逐页根据文字长度和空间范围适应布局；固定风格不等于强制所有页完全相同坐标。设置整批预算、部分成功清单和逐页质量报告。

**验收**：10页系列风格一致、分类含义一致；某页长文字不破坏其他页；换机器缺字体、profile更新、恢复旧风格、用户撤销保存偏好。

### A09 · 自动渲染、导出与多用途交付

**流程**：固定DesignSpec→生成GIS精确内容/整饰→编译受控PS配方→实际预览与检查→选定版本高分辨率导出→核对最终产物→在成果面板显示。

**实现重点**：
1. Pro布局尺寸用物理页单位，DPI在支持的导出参数中设置；本轮读取的ILayoutService明确CreateLayout不提供DPI，不能虚构布局对象的DPI属性。
2. 每个地图框有extent/CRS/rotation/scale绑定，栅格分层采用统一画布和锚点；PS不得随意非等比拉伸地图。
3. PS仅对系统拥有文档执行白名单动作，顺序受宿主模态限制。采用DOM优先、内部审查过的action descriptors补缺，外部模型不得提供任意代码。
4. 字体/ICC/PSB/智能对象/画板/保存重开逐项 `[VERIFY]`；不支持的效果在模板匹配时排除，而不是到最后要求用户手动补救。
5. 规划图可增加版式层次、标题/注释/标识和合法装饰；科研图以可读性、一致分类和精确规格为主。科学栅格/定量颜色保护不能被全局PS调整层破坏。
6. 输出另存新版本，不覆盖原工程与原PSD；支持PNG/TIFF/PSD/PSB等经验证格式；GIS PDF/SVG等由相应原生链交付，实际格式及可编辑粒度在manifest声明。
7. 低分辨率通过不代表最终通过。最终检查尺寸、DPI/色彩声明、文字、图例、比例/北向、引用依赖和文件重开，逐项报告部分成功。
8. 默认提供“打开成果目录”“使用图片”“查看方法说明”；PSD作为可选源文件，不要求用户打开它才能取用最终成果。

**状态区分**：基础GIS输出、完整GIS＋PS输出、部分格式完成、等待引擎、质量未通过。缺PS时原生结果可以合法交付，但不能计入GIS＋PS自动链成功。

### A10 · 自动更新与低摩擦恢复

**默认更新算法**：
1. 加载原任务AnalysisPlan、DesignBrief、已接受Patch和StyleProfile版本；使用新数据建立输入契约。
2. 对可证明未变的步骤复用结果，其余重新计算；弱指纹不复用。算法/参数/CRS/模板/字体/ICC改变都进入依赖失效判断。
3. 生成新的FactTable、DesignSpec与受控文档，沿用已批准的设计意图。自由文字里的旧年份/旧数字不能被当作自动事实：可提示更新，不能猜测替换。
4. PSD与绑定manifest若有外部改变/无法核对，保留原件，把新自动成品另存为分支；默认无需用户逐层合并。
5. 将新旧预览和业务指标差异带回成果面板；方法相同与不同分别标记，不能把纯图像差异直接解释为GIS变化。

**恢复策略**：PS未开/插件未就绪时提供简单引导或等待；宿主忙有界重试；字体问题选择预授权替代并重排；连接丢失先查requestId/输出/文档revision；磁盘不足保留作业，不到C盘另找缓存。

首次启动/配对和每天是否需重新启用插件是技术验证项；启动按钮只使用明确宿主路径和已批准行为，不强杀、自动关闭或操纵用户未保存文档。UXP生命周期需要实际验证，不能假设命令可永久后台存活。[Adobe面板与命令](https://developer.adobe.com/uxp/guides/explanation/concepts/panels-and-commands/)。

自动化不消除宿主许可证或权限要求，也不代表PS自身从不写系统目录。项目产物/缓存/审计均在D盘；主程序和官方安装所需例外另行核实。

## 4. 自动设计状态机与防无限循环

```text
brief_ready
  → semantic_validation
  → analysis_ready
  → layout_candidates
  → preview_rendering
  → checking
      → repair_planned → rendering → checking  [共享全任务修正预算]
      → final_rendering → final_checking
          → ready_for_delivery
          → repair_planned                     [仍有预算才允许]
      → needs_clarification / quality_blocked / waiting_engine

任意执行态 → cancel_requested → cancelled / needs_reconcile
```

每次状态转移持久化specRevision、candidateId、renderId、checks、repairCount、resourceBudget和真实宿主回执。无法确认是否已完成写操作时，进入needs_reconcile，不盲目重发。

以下规则共同限制循环：

- 修正只能使用版本化的有限策略；相同spec＋相同issue集合重复出现时停止。
- 不因评分降低而无界换模板；留存最后一个硬检查通过的候选，但最终文件仍需独立检查。
- 用户取消后的自动修正/新导出不得启动，正在执行的宿主动作按真实取消能力处理。
- 预算耗尽、无合格解、证据unknown影响核心质量时，返回准确状态；不能包装成“已完成，仅建议手动美化”。
- 可选模型的等待、费用/调用预算与渲染预算独立，超限不再调用；核心标准模板不依赖模型可用。

## 5. 外部接口如何承接，避免重复造工具

下面是规划中的职责映射；新增字段/语义和计划版本必须评审，不能把它当当前可执行参数表。

| 现有/候选公开入口 | V5承接内容 | 需要补的内部服务 |
|---|---|---|
| suggest_workflow | 业务场景和成果配方建议 | A01/A02，能力与数据匹配 |
| validate_plan | 检查业务方法、设计计划与预算 | A01/A03/M05，明确验证范围 |
| apply_processing_plan | 执行经批准的工作流 | M04/M06设计适配；需保留旧schema和语义 |
| export/validate_design_bundle | 自动生成与核对地图素材 | A03/A09，坐标/画布一致 |
| ps_apply_design_recipe | 执行结构化设计意图编译出的受控配方 | A03/A06/A07/A09，不接受自由代码 |
| ps_get_capabilities | 自动化前判断实际PS状态/支持操作 | M12/M13及字体/输出能力探测 |
| ps_preview_document | 细粒度预览入口 | 底层预览在M1已实现；该工具在P10正式暴露 |
| ps_validate_document | 细粒度文档检查入口 | 底层检查在M1已实现；P11正式暴露 |
| ps_export_deliverables | 自动保存与导出 | A09及最终文件检查 |
| refresh_design_bundle / ps_refresh_design_bundle | 更新素材与受控内容，V5默认安全新版本 | A10；不得静默改变已冻结候选契约 |
| validate_delivery_package / get_job_report | 交付完整性、自动检查结果与来源 | A05/M16，未知项明确 |

当前源码apply_processing_plan仍是既有步骤格式和受限执行逻辑，不是已经具备通用设计DAG。新内部设计IR可以通过经评审的适配器实现；不能绕过现有批处理限制直接调用宿主，也不能擅自添加公开参数。

**提前实现服务不等于提前注册工具**：M1自动推荐需要预览/字体检查/文字样式等底层能力，这些可以由受控配方调用同一验证内核。P10–P12随后提供更细粒度公开契约并复用服务。工具数量仍按唯一注册逐项计数，不把内部动作、模板和自动工作包加进去。

## 6. 真正减少操作的产品实现

**首屏**：选择数据＋选择用途（规划汇报/科研制图/已有项目风格）＋生成按钮；输出目录和关键方法在启动预览中明确。

**生成后**：大图、已检查摘要、推荐理由、下载/打开成果、改图输入或快捷按钮。备选稿折叠，专家参数折叠，PS技术状态只在异常时展开。

**修改**：默认面向标题、图例、说明、整体风格等语义对象。用户不需要找第17图层、选择蒙版、调混合模式或输入JSON。

**数据更新**：选择原任务→新数据→显示业务影响→生成新版。沿用风格无需逐项重选；对真正影响分析结论的变化仍明确确认。

**恢复**：提供“继续等待”“重试连接”“用基础成图”“保留当前版本”等当前有效动作；用户明确要求完整PS成果时基础版不得自动冒充完成。

自然语言输入由现有AI客户端承接，Pro表单/快捷按钮承接确定动作。若要把聊天嵌入Pro，需另立客户端/模型集成设计；没有模型时也不能让标准场景失去生成能力。

## 7. 自动设计数据与测试资产

拟D盘拥有根内结构，实际路径在工单配置并探针；以下不是本轮创建目录：

```text
design-workflows/<jobId>/
  brief.json
  analysis-plan.json
  design-specs/<revision>.json
  accepted-patches/<revision>.json
  candidates/<candidateId>/layout.json
  previews/<renderId>.png
  checks/<renderId>.json
  owned-documents/<revision>.psd-or-psb
  deliverables/<version>/manifest.json
  events/step-records
```

manifest包含文件身份、输入/数据/模板/风格/字体/宿主版本、来源和检查coverage。清理仅作用于可证拥有的缓存，不删最终成果、外部原件、未知锁或用户后续修改。

| 测试组 | 至少覆盖 |
|---|---|
| 排版 | 长中文/混排、极端长宽比、密集图例、多图框、固定页数、无可行解 |
| 地理保护 | 改页面仍保持比例/北向/legend，科学颜色不可被全局调整破坏 |
| 自动修正 | 修正成功、重复问题、修正引入新问题、预算耗尽、最终分辨率才出现问题 |
| 用户改稿 | 常见20类意图、歧义、过期revision、撤销、只改标题不跑GIS分析 |
| 更新 | 更换数据、样式锁、绑定文字、自由文字旧年份、外部PSD修改原件保护 |
| PS运行 | 未安装/未开/插件关闭、面板隐藏、模态忙、保存/重开、断线、取消、宿主崩溃 |
| 交付 | 多格式部分失败、错误DPI、字体替代、ICC/打印限制、原生/PS版本明确区分 |
| 无PS技能 | 不讲图层/蒙版术语、无设计师代操作、首次配置与日常步骤分开计时 |

验收依赖实际运行与成图，不通过文档或接口存在宣称自动设计完成。版本差异标NOT VERIFIED，执行只交PASS CANDIDATE，由独立验收方裁定。
