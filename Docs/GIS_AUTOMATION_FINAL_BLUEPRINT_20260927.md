## 3. 最终产品定位

**把项目做成“从空间资料到专业成果”的自动生产平台。**

用户交出资料、用途和约束，系统完成数据理解、质量检查、方法选择、分析、专业制图、PS排版美化、自动检查与有限修正、多格式交付；以后一句话修改或替换新一期数据，沿用可追溯的分析与设计意图生成新版。

两种入口共享同一内核：

- **普通用户：** ArcGIS Pro 工作台，场景卡片、结构化表单、预览和快捷修改；没有模型账号也能走标准模板任务。
- **AI/专业用户：** 已验 MCP 客户端，自然语言与细粒度工具；模型输出计划后仍通过同一执行策略和检查。

Pro面板首版不暗含一个已经接好的大模型。自然语言由已配置客户端提供；将来如加入面板内模型适配，也要有独立凭据、成本、数据外发与测试设计。

## 4. 八项核心创新及其实际作用

| 创新 | 怎么做 | 用户能感受到的改变 |
|---|---|---|
| 成果需求编译 | 把用途、受众、尺寸、输入、方法、预算编译为可检查的 TaskBrief/AnalysisPlan | 用户说“做汇报图/论文图”，不用先理解工具目录 |
| 事实与设计分离 | 统计、单位、分类、来源保存在 FactTable；DesignSpec 只引用已计算事实 | 改风格不会改数据；换数据后数字、图例和说明一起更新 |
| 自动版式求解 | 模板定义语义槽位、约束、备选布局与真实字体测量 | 标题变长、图例变多、横竖版切换时自动重排 |
| 科学表达保护 | 地图框变换、单位、比例尺、图例分类、定量颜色、事实数字均受硬规则保护 | 图更美观，同时不把空间关系和分析结果修错 |
| 有界自检查修正 | 真实渲染后检查；只有白名单修正规则；预算共享、无改进停止 | 常见溢出和碰撞自动处理，出错有明确原因，不让用户去学PS补救 |
| 意图版本化更新 | 用户接受的修改保存为 DesignPatch；换数据默认完整重渲染新版 | “沿用上月风格”可复现，外部改过的PSD仍保留 |
| 一源多成果 | 同一事实表和语义设计输出地图、图册、汇报页、PPTX、长图、报告 | 不用在几种软件间反复抄数字、换图、对版本 |
| 能力与环境自解释 | 目录按任务搜索，逐项显示许可、宿主、数据、可用证据 | 不再先尝试一串不可用工具后才知道缺条件 |

这些是本项目的组合设计方向，不声称每个单项为全球首创。长期优势来自经真实项目检验的“领域方法＋设计规则＋失败修正＋基准数据＋更新证据”积累。

最终追求命名工具数量和独立业务能力均超过冻结的同类比较集合。**不为守住290而拆接口；也不以“已有通用入口”替代逐算法、逐场景的真实实现。** 基础242是治理候选基准；F03给出实际独立契约数，并从有价值的扩展候选承接真实缺口。若原16项全合并，仅相对这些16项的候选算术为274；这不是最终下限，其他候选仍可能合并。

能力广度覆盖：数据接入/治理、空间与网络、栅格遥感、时序、三维与点云、统计与不确定性、地图出版、PS自动设计、报告/PPTX/长图、离线与受控在线交付、持续更新与恢复。

受控GP不再无名承诺“150种均可用”。保留拓展规模目标，F03按全部场景反推逐算法名册，分别记录原53、新申请、许可限制和实测覆盖；专用封装与其底层算法不重复计能力。

## 6. 普通用户的完整流程

**首次设置：** 安装已验插件 → 检测Pro/PS/许可/字体 → 简单连接引导 → 选D盘工作目录 → 用自带样例确认能出图。官方安装、配对或目录权限可能需点击；不要求开发者模式、不要求图层知识。首次设置与日常操作分开测量。

**日常四步：**

1. **选资料和用途。** 拖入拥有的文件夹/GDB/表格/影像，或选项目图层；选规划汇报、科研论文等用途。
2. **确认任务卡。** 系统显示识别结果、必要歧义、分析方法、输出目录、预计成本/时间和交付物；一次批准范围内自动执行。
3. **看成稿或说修改。** 默认展示一张已检查的推荐稿，最多两张备选；“更简洁、图例移右侧、改横版、突出主要道路”等转为可撤销设计修改。
4. **取成果，以后更新。** 地图、报告、PPTX等按选择输出，附来源/方法；新一期数据进来后提示受影响成果并生成新版。

用户不需要手工导入图层、建蒙版、调字号、搬图例、改PS图层。程序遇到无解版式、缺许可或未知副作用时，给出简明状态与可行动选项；不会要求用户自行进入PS修图才算完成。

任务卡一次批准不是无限授权：输入、方法、拥有输出根、允许操作、预算和自动修正范围绑定版本。改变方法、覆盖原件、外发或新增范围才重新确认；单纯在范围内改风格不用逐工具确认。

## 7. 两个端到端示例

### 7.1 规划汇报：公共设施服务与候选选址

输入设施、人口、行政区和有效路网；系统先检查CRS、人口单位、路网阻抗与许可。数据只足以计算直线覆盖时，任务卡说明限制，不把缓冲区冒充15分钟路网服务区。

用户确认“比较现状覆盖，增加三处设施，输出A3汇报图＋6页PPTX”。系统计算覆盖/OD/选址，对服务人口与未覆盖区生成事实表；自动制图，PS完成标题、层级、装饰和排版；地图/图例/数字硬检查通过后交付。若用户只改“更适合领导汇报”，调整信息层级，不重跑求解；若改“只建设两处”，重新计算并同步全部数字和图件。

### 7.2 科研表达：多年土地覆被与变化可信度

输入多期影像、产品说明、参考样本和研究区；系统检查时段、云影、共同格网、量纲、训练/验证分离。产出分类/变化、精度和必要的不确定性结果。

用户确认双栏论文图＋补充表。系统自动生成研究区、分类图、变化图、混淆矩阵/误差图、方法和数据来源；PS统一版式和中文/英文排版，保护定量色阶与比例。没有独立参考数据时明确“精度未验证”，不会编造高准确率；补数据后重跑对应依赖并生成新版本。

## 9. 自动化的可靠边界

- 地理和统计计算由受控工具完成；模型不能自由发明数值或执行任意代码。
- PS默认承担视觉制作；无PS时可交基础GIS结果，但不能标成全链完成。
- PSD中的GIS素材可为语义分组、智能对象或栅格；不承诺每个GIS要素变成可编辑PS矢量。真正矢量需求由GIS原生PDF/SVG等独立交付。
- 定量颜色、几何位置、比例尺、分类和事实数字不能被美化覆盖。装饰性生成素材如需引入，只进入非数据区；首版不依赖生成式图片服务。
- 视觉模型只提供辅助检查，默认不上传项目图像。外部服务需明确提供者、数据范围、成本和授权。
- 外部PSD已改时保留原件，生成新版；普通用户不用解决逐层合并冲突。
- 配置、日志、缓存、中转、作业都在已探针的D盘拥有根。官方宿主自身的系统写入需单独界定；不能虚假保证商业宿主完全不写C盘。

## 10. 是否继续是插件，能否一键安装

**可以继续采用插件形态，目标是一个安装入口部署整个系统。**

交付组成：ArcGIS Pro `.esriAddInX`＋Photoshop UXP `.ccx`＋模板/规则/支持矩阵/教程＋安装与恢复引导。用户正常使用不需要UDT或开发者模式；Adobe官方支持独立CCX的安装方式，但仍可能有权限或第三方包确认。[Adobe安装文档](https://developer.adobe.com/uxp/guides/how-to/distribution/install/)

这里的一键是统一入口、自动检测和尽量少的必要确认，不承诺任意机器全程静默；也不包含ArcGIS Pro、Photoshop或它们的商业许可证。

**顺序固定：功能全部验收 → 安装器扩展与制包 → 用真实包测试首次安装/升级/失败恢复/卸载 → 发布验收。** 当前D-081/r21是旧基线维护分发，按原工单继续；不等于提前制作本方案的全功能包。

## 11. 何时可以说“明显领先”

以冻结日期和版本的六个公开项目为首组参照：能力同口径清点、共同任务同条件评测、新手完成率与专业盲评并行。

最终门槛包括：108标准图全部自动完成；严重科学错误为零；60场景真实跑通；独立盲评和新手试测达标；共同任务成功率不低于最优对照，并在至少两项用户指标达到预设实质改善。详见验收文件。

“全面超越”作为本项目明确目标；可对外使用的领先表述以最终证据范围为限。持续更新竞品矩阵有助于迭代，但每一发行版在测试前固定范围，不以不断加功能拖住本次发行，也不在测试失败后悄悄缩范围。
