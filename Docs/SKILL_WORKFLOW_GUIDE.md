# Skill 与任务面板使用教程

适用发布：2.1，Skill0.7.7。它把用户目标组织成可查看、可核验的业务流程，不会仅因安装Skill便新增GIS算法。完整安装方法见[安装教程](SKILL_INSTALL_GUIDE.md)，实现与边界见[2.1更新说明](RELEASE_2_1.md)和[面板说明](PROGRESS_PANEL.md)。

## 用户如何开始

在支持项目Skill的客户端打开自己的工作区，让其加载 `.agents/skills/arcgis-pro-2-workflows/SKILL.md`。首次制作提供三项：要完成的分析、数据实际位置、全部结果保存位置。已经说过的内容不必重复。例如：

> 使用 D:\业务资料 中的道路、建筑和影像做设施布设与影响分析，全部工程、数据、预览、报告和记录保存到 D:\业务成果。先展示完整处理及检查流程，关键步骤给真实预览，完成首检、修复、复检与交付检查。

Agent先读数据、实际工具schema、许可和工程状态；重要资料不全时列出补充清单，写明用途、格式/范围/精度建议、受影响步骤和可接受替代。可独立的只读预检继续，依赖缺失资料的分析保持受阻。不会自动用示例数据替换用户资料。

## 如何选择适合业务的流程

以用户目标、真实输入、时相/坐标/单位、行业技术设计条款、当前能力和成果规格组合计划。模板是候选，不是固定答案。优先现有已支持工具；缺入口先评估受控工具组合是否科学等效，明确条件与限制。确无替代才提出开发范围，并取得用户开发同意。用户明确允许时可用Pro原生界面补齐，保留参数、消息与成果核验；这不意味着缺失算法已经变成MCP工具。

水文计划可包含DEM预处理、洼地诊断/填洼、流向、累计、河网阈值与提取、矢量化、出口定位、流域和指标统计，再接检查修复复检。目录中已有部分水文GP候选，但每一步仍须核实时schema、许可与小样本执行，不能把计划完整当成可执行性已验证。

建筑/阴影任务额外核真实Z、相对高度、地面模型、日期、时区和DST。地面阴影需和地下延伸阴影体区分；轮廓转面后的分面数不必等于输入建筑数。旧报告答案不是计算依据。

## 聊天和面板怎样一起看

| 位置 | 应看到的内容 |
|---|---|
| 聊天首次计划 | 完整业务步骤、依赖、方法依据、精确输出和待确认项 |
| 聊天阶段卡 | ▶当前步骤、已核验结果、下一步、阻断项、最近真实观测时间 |
| 面板主视图 | 完整步骤与检查重点，所有真实RUNNING行高亮，顶部当前状态 |
| 步骤详情 | 方法、输入输出、参数来源、所选工具、实际结果与证据 |
| 检查与修复 | 预检、过程检查、复检、最终检查，缺陷和受影响下游 |
| 内部进度 | 实际请求ID、事件来源、真实后端计数与最近事件 |
| 资料与交付 | 需求/数据/输出确认、补数建议、实际成员与绝对路径 |

点击别的行只改变查看对象，不改变正在执行步骤。“跟随当前步骤”控制是否自动定位；窗口刷新约500ms，不代表Agent已经发布新事件，也不代表聊天自动更新。Agent必须在真实开始、返回、发现问题、修复和复检时发布同一记录，并直接发聊天更新。没有内部回调时明确显示未知，不编造进度百分比。

2.1山海景观按本机时间自动切换，动态装饰与正文分区，背景属于装饰而非任务地图。无需手动换背景或开关特效。主视图提供步骤搜索、需关注筛选和定位当前，完整依赖步骤仍可查看。检查入口汇总当前任务全部待处理检查，不随步骤筛选缩小；0项待处理也不证明已配置全部行业检查。

原生GP的界面进度与MCP内部事件分别标记。面板和原生参数窗重叠时并排摆放；物理键鼠操作前确认前台属于Pro，不能把快捷键发给其它软件。暂停、关闭观察窗口、取消后端任务不是同一动作。

## 如何检查与领取结果

工具成功只是“已产出待核验”。首检对数量、字段、范围、CRS/单位、方法、完整覆盖及真实图像逐项检查；失败保留原报告，修复后重算受影响下游。复检重新读实际成果产生新证据，最终再核文件、完整成员、格式、工程依赖、图像规格和报告一致性。

默认不覆盖原件。任务改方法或数据版本后，旧检查可能失效，面板不会继续拿旧绿色状态冒充当前成果。几何工具四项检查、拓扑六类规则应按业务适用性选择，不等同于全部Esri拓扑或行业认证。合法环区孔洞、自然河源和道路端点不能为追求全绿被强制修坏。

结束时聊天与面板逐件列成果名称、绝对路径、格式和核验状态，计划文件不冒充已生成文件。技术自检通过提交PASS CANDIDATE；用户或有权独立验收方另行裁定，Agent不会自批独立PASS。

## 发布记录的维护入口

`scripts/publish_workflow.py`在发布前校验任务合同，以目标目录内临时文件和原子替换更新 `WorkRoot/task-record.json`，保留历史并使用单写锁。`render_task_board.py`只读生成聊天状态板；它本身不执行GIS、不发送聊天、不测量科学真值。仅有远程MCP而无本地脚本执行能力的客户端，应显示面板同步缺口。

发布示例：

```powershell
python -B '<Skill路径>\scripts\publish_workflow.py' `
  'D:\业务成果\本次任务.json' `
  --target 'D:\业务成果\运行记录\task-record.json'
```

不要拿开发夹具、历史预览或300次事件压力检查宣称300种业务功能通过。当前发布验证与未验证边界见[2.1更新](RELEASE_2_1.md)，旧综合实验参考[0.7.1历史记录](SKILL_071_RELEASE_NOTES.md)。
