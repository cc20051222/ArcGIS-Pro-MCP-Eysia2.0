## 一、输入档案

- **分析输入策略**：`domain-known-answer-required / NOT-AVAILABLE-PENDING-USER`。
- **所需数据**：车场/仓库（depot）、订单（orders，含位置/需求量/时窗）、车辆（容量/工时）、路网与阻抗。
- **合格输入现状**：无 VRP 求解器条目（白名单 0 of 53）、无网络数据集 ⇒ `NOT-AVAILABLE-PENDING-USER`。
- **负向档案（invalid）**：订单不可定位、车辆容量缺失、时窗不可行、无求解路径 → 安全拒绝；未分配订单须保留在分母。

## 二、比较规则引用（逐字 ID，零自定义）

- `GBC-001`（证据等级/记账）
- `KDA-001`（G-DOMAIN 已知答案四件）
- `NFD-001`（网络结果失败可见、成本面≠行驶时间）
- `NUM-001`（计数自洽）

## 三、压力维度

- **ST-M4-17**：一车装不下的订单（dimension: vehicle routing where one order fits no vehicle）；预期 **COMPLETE**——该订单列为 undistributed 并点名绑定约束，保留在分母，不静默丢弃。
- 通用延伸：多车多订单、密时窗、订单超容量；FINAL §4 命名未枚举的其余压力 ID 待后续批。

## 四、判据引用（规则要点，不新增阈值）

- 回显网络源/阻抗/单位/方向/时窗，列出未定位订单、未分配订单、求解终止原因（NFD-001）。
- 已定位＋未定位＝输入总数；unserved/undistributed 清单完整（NFD-001/NUM-001）。
- 批量分页：每车一页并保留订单身份；同源：时序表与路线几何绑同一次运行（design demands）。
- 无求解路径时 BLOCKED 点名前置（KDA-001/NFD-001）。

## 五、输出契约

- **副作用类**：file-output（新数据集，拒绝覆盖，D 盘）。
- **语义槽位**：title, depot, orders, vehicleRoutes, timeWindowTable, undistributedOrders, loadBars, units, source, mapFrame, legend, revision。
- **交付物**：配送路线空间图＋时窗/时序表＋装载图＋未分配订单清单＋方法 TXT。
- **规划工具**：optimize_vehicle_routes（X40，VRP，M4 批，**未实现/未验收**）。
- **[VERIFY]**：VRP 求解器、Network Analyst 许可、订单/车辆数据 NOT VERIFIED。
