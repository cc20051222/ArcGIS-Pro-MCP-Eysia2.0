## 一、输入档案

- **分析输入策略**：`domain-known-answer-required / NOT-AVAILABLE-PENDING-USER`。
- **所需数据**：候选设施集（candidateSet）、需求点/需求量、设施容量、目标函数（收益/覆盖/成本）、（可选）公平性口径。
- **合格输入现状**：无网络数据集与 location-allocation 求解器（白名单无条目）⇒ `NOT-AVAILABLE-PENDING-USER`。
- **负向档案（invalid）**：候选设施不可定位、需求/容量缺非零分母、目标函数未声明 → 安全拒绝；公平性计算需合法分组与非零分母（TP17 纪律）。

## 三、压力维度

- 主场景 S56 **未在 M4 压力子集 18 行中单独建档**（如实标注）。
- 通用压力方向（FINAL §4 命名未枚举）：候选设施数量大、需求远超容量（大量 unserved）、多目标权衡、含不可定位候选；预期 COMPLETE（分配表完整、unserved 列出）或 REJECT（无求解路径 BLOCKED）。压力 ID 待后续枚举。

## 四、判据引用（规则要点，不新增阈值）

- 每个图件来自同一张分配表（same-source）；批量分页每个备选一页、分级一致（design demands）。
- 已选设施、分配需求、未服务需求须分别列出并与目标表一致（NFD-001 失败可见）。
