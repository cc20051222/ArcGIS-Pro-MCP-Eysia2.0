## 2. 五本账与每项证据

每个能力矩阵行必须具有：项目版本、领域/语义操作、输入前提、输出、副作用、许可/宿主、可调用入口、官方声明证据、源码证据、运行证据、独立验收证据、限制、对应本项目候选/场景、负责人。

计数包括：

1. **命名接口数：** Registry与真实tools/list一致；废弃别名/未实现占位不算交付新增。
2. **独立语义操作数：** 不因拆成多个接口、多格式或多模型重复计数。
3. **GP算法数：** 逐名白名单、包内资源、本机许可与已测参数范围；通用执行器不是无限已验算法。
4. **完整任务数：** 从输入到交付、改稿与更新的场景证据；一组API成功不等于完整任务。
5. **实际可用能力数：** 按宿主/许可/模型/格式组合计算，拒绝把另一机器的能力默认到当前用户。

每项证据等级按 `DECLARED / SOURCE VERIFIED / RUNTIME VERIFIED / E2E VERIFIED / INDEPENDENTLY ACCEPTED` 显示，缺证据为NOT VERIFIED。执行交付只用PASS CANDIDATE。BLOCKED和NOT VERIFIED不得隐藏在通过率之外。

## 3. “数量质量领先”的可验收目标

| 维度 | 最终目标与比较办法 |
|---|---|
| 命名数量 | 实际验收数超过冻结的同类单项目同口径命名接口数；290只是待去重池，不能拿规划数比已发布数 |
| 语义广度 | 冻结的目标领域高频能力100%覆盖；全部适用行逐项说明本项目覆盖/缺口。存在实质缺口时不得宣称该范围全面领先 |
| 领域深度 | 数据/分析/设计/交付各域有真实任务和数值/质量证据；PS操作数与PS接口数分开，不借全平台总量声称PS所有功能最多 |
| 共同任务成功 | 在相同数据、许可、模型/上下文、硬件、时间预算和人工介入规则下，本项目成功率不低于最优对照 |
| 用户效率 | 共同任务上人工操作时间目标降低≥50%；完整任务墙钟耗时目标降低≥30%；分别报告中位数/P95与分组，不能只选最快样本 |
| 专业视觉质量 | 双盲/随机顺序评价，胜率＝胜数/全部有效配对评价（平局进分母），目标≥70%；无效评价排除规则预先固定；区间按样例/评阅者相关性报告 |
| 自动化 | 全部标准任务0次PS人工设计；首次配置/业务批准/异常恢复另外计数，不能隐藏人工代操作 |
| 可信与恢复 | 严重空间/数值错误0；已定义故障与恢复矩阵通过；无法对账时安全停，不能错误重试覆盖原件 |

“明显领先”发布证据要求：先通过自身全部功能门；共同任务成功率不落后；效率/人工时间/视觉偏好三项至少两项达到预先冻结的实质改善阈值，并披露样本量和区间。若区间不足以支持优势，只报告探索性结果，增加样本或缩小结论范围；不得改阈值追求漂亮结论。

对于竞品不具备的GIS→PS完整链，报告能力有无与本项目真实成功率；不把对方不适用样本强塞进共同任务分母制造速度优势。比较实验同时有“各自最佳可用配置”和“控制模型/资源的共同配置”两组，防止把更贵模型带来的收益全部归插件。

不能笼统保证世界上所有开源项目的所有功能永久落后；正式结论必须带对标集合、版本、范围和证据日期。新能力出现进入下版差距池，不无限追涨本次发行范围。

## 4. 60场景与108标准图的完成门

| 集合 | 数量与设计 | 完成标准 |
|---|---|---|
| 场景 | 能力目录S01–S60，每条至少一条完整任务＋关键负例＋更新用例 | 方法/许可/输入条件、真实分析、成果、追溯齐备；若对应场景不产生地图，不能强算模板样例 |
| 标准图 | TP01–TP18、TS01–TS18，各3种冻结输入，共108 | **108/108在预算内自动通过，0次PS手工设计**；最终文件重新检查 |
| 首轮质量 | 上述108首次真实渲染 | 无需修正比例目标≥90%，即至少98例；剩余例最多2轮获准修正 |
| 压力集 | 至少40例，长中英标题、密集图例、多图框、极端形状、字体替代、改稿和多页 | 事先判定适用集自动完成率≥95%；失败完整披露，任何严重科学错误均阻断 |
| 核心控制任务 | 24任务×至少3轮，覆盖发现/分析/批量/取消/恢复/更新/交付 | 顺序、数据和错误注入可复现；重复轮不冒充独立用户样本 |
| 隐藏集 | 至少12条事前冻结且适用的陌生变体，覆盖两类设计与新领域 | 冻结候选版本首次测试自动完成率≥90%（12例至少11例），最多2轮获准自动修正；成功产物科学硬门全过、严重科学错误0。修复已见例只算回归，重新检验泛化需另一套未见集 |
| 可拒绝输入 | 无许可、无CRS、无参考误差、已知无解版式、未批准外发等 | 正确拒绝和可理解理由；不能计入“成图成功” |

适用规则、样本hash、数值容差、最小字号、色差/配准阈值、严重度均在看最终结果前冻结。保存失败/超时/断线不能事后移出分母。另报告全尝试分布：完整、基础GIS、部分完成、阻断、取消、失败；缺PS只完成基础图不算全链成功。

## 5. 地理、数值和视觉质量分别验

| 类别 | 必查项目与证据 |
|---|---|
| 地理一致性 | CRS/转换/单位/范围/轴方向/Z基准；样点/控制点；图框变换、指北针、比例尺、图例与来源数据一致 |
| 数值正确性 | 已知答案/解析或可信参考；距离/面积/分类数量/人口分母/NoData；路网可行性；统计假设/验证分离/误差来源 |
| 科学保护 | 定量色阶不被全局或父组效果污染；关键地物不被装饰遮挡；事实文字绑定有效FactTable；禁止修饰制造显著性 |
| 排版 | 实际PS渲染中的长中文/混排、字体fallback、字重、标点、行距、最小字号、溢出/裁剪/图例碰撞；不能仅信WPF测量 |
| 可访问性 | 色觉差异、灰度打印、低视力可读性、符号/纹理辅助、标题与图例层级；检查条件/量表先定 |
| 输出/印刷 | 物理尺寸、有效像素/DPI、ICC/位深、透明度、字体、PDF/SVG矢量属性、PSD/PSB重开；屏幕好看不代表可印刷 |
| 多媒介 | 地图/报告/PPTX数字一致；PPTX文字和承诺可编辑的图表实际可编辑；长图与多页不漏图例/来源 |
| 版本更新 | 数据变更后数字/图例/说明同步；已接受视觉意图保留；外部PSD与用户原件无覆盖；旧revision拒绝 |

至少两名独立制图/设计评阅者按冻结量表评阅。初始建议五分制均分≥4、单项不得低于3；F05定标后固定。科学正确性是单独硬门，不能被美观均分抵消。

## 6. 无PS用户的真实体验验收

开发期8–12名无PS经验用户用于找问题；G-FUNCTIONAL前另组织至少24名目标用户，每人至少2个任务，在已配置的受控功能环境检验规划/科研、业务引导、连接、改稿和更新。预计至少48个任务观察，按参与者/任务分组报告，重复任务相关性不能当独立样本计算夸大精度。此阶段不使用尚未开发的统一安装器，也不能代替R阶段实包首次安装试用。

独立完成率目标≥90%，0次设计师代操作；需要研究员提示的任务单列辅助完成。业务决策点击、连接引导、PS设计动作、异常介入次数与时间分开记录。R阶段另招无安装经验的用户使用真实包，单独测安装/权限/配对/首次成图，不依赖研究员预配置。专业审阅者可改规则/模板，不能替测试用户把成图修好后记“全自动”。

典型验收话术是“做一张可直接用于汇报的图，并更新下月数据”，不给内部工具调用清单；检查用户能否发现成稿、理解阻断、拿到文件和确认新旧版本。

## 7. 规模、资源和性能矩阵

以真实目标硬件冻结数据规模与阈值。初始试验档位用于发现瓶颈，不是现有能力宣传：

| 领域 | 建议规模档 | 必记指标 |
|---|---|---|
| 矢量 | 1万/10万/100万要素，同时记录顶点/字段数 | 扫描/分析耗时、峰值内存、缓存和取消响应 |
| 栅格 | 1千万/1亿像元；不同波段/位深、掩膜比例 | I/O、分块边界、CPU/GPU/内存、临时盘、产物校验 |
| 点云 | 1百万/1千万/1亿点，目标机器分级支持 | 索引/读取/分类耗时、分块/密度与Z误差 |
| 设计 | A4/A3、300DPI起测；大画布/PSB单独支持档 | 首预览、最终导出、PSD重开、层数/像素/内存 |
| 批量 | 1/10/100页和连续作业 | 总预算、取消控制、每页一致、恢复重复写 |
| 交互 | 目录检索、状态、预览、普通风格改稿 | 本机控制响应目标P95<1秒；小型标准预览初始目标<30秒，须F04按硬件定标 |

若硬件不支持最大档，明示支持上限和错误行为；不能把小样例成功写成无上限。数据总量、几何复杂度、波段与图层同时报告。性能缓存结果和首次结果分开，禁用“暖缓存对冷启动”的不公平比较。

## 8. 故障、版本和兼容验收

- 现有154工具契约回归、唯一Registry、只读、许可/路径/批准、错误码/嵌入白名单同步。
- 旧JSON、D-077期断点、D-079 JSONL/sticky载体；日志尾损、压实时中断、同job并发、旧owner迟到、跨重启接管。
- GP取消不立即可中止、PS忙、宿主退出、intent后崩溃、产物已写receipt丢失、磁盘满、token失效、端口冲突。
- 用户在PS编辑另一文档、选择变化、外部修改母版、重复点击、旧意见、新数据指纹变化、部分导出成功。
- 首个主Pro×PS组合全部E2E；其他承诺支持组合按风险分组验证，发现API/渲染差异则扩大到相关全用例。net6/net8不能替代宿主版本证据。
- 字体与ICC版本被记录；新增字体/主程序版本触发相关回归，不把任意机器当同一环境。

Adobe版本和插件生命周期必须真实核定，不能从PowerShell版本、CCX存在或静态API说明推定已可日常生产。

## 9. 最终功能门与安装门

**G-FUNCTIONAL：** 冻结业务范围及批准的补差均有证据；60场景、108标准图、压力/隐藏、数值/故障/版本与新手门通过；严重缺陷归零；文档、模板/模型/字体来源、许可与限制齐备。NOT VERIFIED开关不代表完成。

G-190暂缓的在线三项列入完整范围的决策门：执行前须单独审查。若最终不获准，必须由用户明确从该发行范围移出并如实标注本地版边界；不得执行者自行忽略，又宣称在线全链完备。其他不可实现候选同样通过显式变更记录处理。

**R01–R04：** 功能门之后实现安装器扩展、固定组件hash/manifest、制作候选包、用实际包做安装/升级/重复安装/部分失败/取消/恢复/卸载及首次出图。客户端配置只改明确选中的目标，陈旧备份拒绝覆盖后续用户修改。官方宿主/插件必要系统位置明确列出，不把D盘项目约束误写为商业软件完全不写C盘。

**G-RELEASE：** 功能候选与安装包内容一致；Pro/PS插件和资源版本一致；实际安装后的工具/许可/配对/成图可用；支持矩阵、教程、诊断/恢复齐全。签名和公开发布按授权执行。新全功能统一包的制作顺序不改变现D-081维护分发授权。

G-LEAD与G-FUNCTIONAL分开：功能可用不等于竞争领先。比较证据未达标时，修正产品或如实发布功能事实，不能把营销目标当验收结果。
