## 1. 它是怎么工作的（一句话）

```
你的 AI 客户端  ⇄  (本机 6520 端口的 MCP 服务)  ⇄  ArcGIS Pro（正在打开你的工程）
```

* 服务跑在**本机**，只监听 `127.0.0.1`，不对外暴露，不需要公网。
* 你能用的能力 = ArcGIS Pro 当前打开的**工程/地图/图层/数据**，加上它跑的**地理处理工具**。
* 因此：**Pro 必须先打开工程，并在 MCP 选项卡点 Start**；否则客户端调用会失败。

## 2. 每次使用前的 3 件事

| # | 动作 | 判断成功的标志 |
|---|---|---|
| 1 | 打开 ArcGIS Pro，并打开你要处理的工程 | 有一个活动地图视图（有视图才能做"当前地图"类操作） |
| 2 | Pro → **MCP 选项卡 → Start** | 一键窗口诊断显示 6520 监听 |
| 3 | 你的 AI 客户端开新会话 | 工具列表里有 **239** 个工具 |

> 提示：MCP 服务随 Pro 的 Start 起、随 Pro 关闭停；退出 Pro 后客户端自然就连不上了。

## 3. 连接验证（逐个客户端确认"真的连上了"）

> 安装成功 ≠ 客户端连上。**只有各客户端自己发起会话并成功调用工具，才算连接级验证通过。**
> 下面按"先通用、后分客户端"的顺序做，每步都记录结果（通过就勾，不通过就如实记失败原因）。

### 3.1 通用前置（每次都一样）

> ### ⚠️ 顺序很重要（实测踩到的坑）
> **必须先启动 ArcGIS Pro 并点 Start，再打开/新建客户端会话。**
> 客户端的工具列表是在**会话建立时**确定的：如果会话是在服务未启动时建立的，里面**根本看不到** ArcGIS 工具
> —— 即使配置文件完全正确、`6520` 随后已监听也一样（旧会话不会动态补上）。
> **补救**：让 Pro 处于 Start 状态，然后**关掉客户端重开**（或新建会话）。

1. ArcGIS Pro 已打开工程 → **MCP 选项卡 → Start**（`6520` 开始监听）
2. 一键窗口点「诊断」，确认 HTTP 层两项：**`tools/list = 239`** 且 **`ping = pong`**
3. 客户端**关闭后重开**（或新建会话）—— 旧会话不会加载新工具

### 3.4 连接失败对照表

| 现象 | 最常见原因 | 处理 |
|---|---|---|
| 客户端里看不到任何工具 | ①**会话建立时服务还没起**（顺序错了）②会话是旧的 / 客户端没重启 | 先让 Pro 处于 Start，再**关闭客户端重开**（或新建会话） |
| 全部工具都调用失败 | Pro 关了（服务随之停止） | 重新打开 Pro → MCP 选项卡 → Start |
| 报端点不可达 | `6520` 没监听 | 上一步做 Start；确认没有被防火墙/安全软件拦 |
| `PORT_OPEN_NOT_MCP` | 6520 被**别的程序**占用 | 关闭占用者后重启 Start；**端口开着≠连上了** |
| 工具数少于 239 | 连到了旧版本服务 | 确认只装了本插件一个版本；重装后重开客户端 |
| 写操作报错 | 参数/图层名/输出已存在 | 先让它只读报告现状（见 §6 注意事项） |

## 4. 怎么跟它说话（示例提示词）

直接用自然语言即可（中文/英文都行），让它调用工具、把结果讲给你听：

| 你想做什么 | 可以这样说 |
|---|---|
| 了解工程 | "列出当前工程的路径、版本和许可信息" |
| 看地图内容 | "列出当前地图里的所有图层，以及每个图层的要素数量" |
| 查字段 | "列出 L_Points 的字段、别名的类型" |
| 按条件选要素 | "在 L_Points 里选出 POP 大于 10000 的要素，并告诉我选了多少个" |
| 改别名字段 | "把 L_Points 的 NAME 字段别名改成 名称"（写操作，见 §6） |
| 空间分析 | "对 L_Points 做 500 米缓冲区" |
| 制图出图 | "新建一个布局，加标题、图例、指北针、比例尺，然后导出 PDF 到 D:\out" |
| 排障 | "调用 ping 和 python_bridge_ping，告诉我是否都正常" |

> **写清楚三件事**：数据在哪（图层名/路径）、要什么参数、结果放哪。AI 客户端会把这些翻译成工具调用。

> - **`get_environment` / `set_environment`**：**会话级**（不落盘，重启失效）。Pro SDK **没有常驻 GP 环境的读回接口** ⇒ 设置为"保存 + 每次 GP 调用下发"，未设置项列在 `unset`（**不伪造值**）；`reset=true` 还原到会话初始态。
> - **`set_readonly_mode`**：会话级开关。开启后**写类/破坏类（84 件）在执行前被拒绝**（`PERMISSION_DENIED` + 消息带 `(read-only)`），**只读类（56 件）与会话/视图态（9 件）不受影响**；**错误码零新增**。
> - **`snapshot_project` / `restore_snapshot`**：快照 = APRX + 图层引用清单 + 断点记录 + **SHA256 清单**；**恢复是破坏性操作 ⇒ 必须 `confirm=true`**；恢复**之前**先做完整性校验，**快照损坏或被篡改 ⇒ 拒绝恢复**（不会"尽力恢复"）；恢复前会把当前 APRX 自动备份为快照目录**之外**的兄弟文件。快照目录须在 **D 盘**（**禁 %TEMP%**）。
> - **`diagnose`**：只读体检；**不可判定项一律 `Unknown`**（不会伪装成 Ok）；某端口/组件不健康时会给 `recommendedAction`。
> - **`export_map_series`**：布局**未启用 map series ⇒ 直接拒绝**（**不会静默退化成单页导出**）；页数超过 `maxPages` ⇒ 拒绝（**不会静默截断文件**）。请先在 Pro 的布局中启用"地图系列"。
> - **`activate_map`**：属 UI 联动；环境不支持时**如实返回 `activated=false` + 说明**（不伪报成功）。
> - **`list_folder`**：只接受**绝对路径**；深度最多 5 层、条数最多 2000；**受保护根拒绝**；符号链接/联接点**不穿越**。
> - **`add_fields`**：**缺省拒绝已存在字段**（列入 `skippedExisting`，不报错）；字段规格非法则**整批不提交**。
> - **`get_project_items`** 的"工具箱"来自工程 home 目录下的 `*.tbx` / `*.pyt` **事实枚举**（不是工程注册项）。

## 6. 使用注意事项（很重要）

1. **写操作先备份**：`add_field` / `alter_field` / `calculate_field` / `delete_dataset` / `rename_dataset`
   会**真实修改你的数据**。动手前先复制一份数据集，或在工程里用副本试。
2. **GP 输出会落盘**：缓冲区、裁剪、合并等会产生新数据，请明确告诉它输出路径（例如 `D:\out\xxx.gdb`），
   不要让它写进系统盘或你的原始数据目录。
3. **先只读后写**：让它**先**用只读工具报告现状（图层、字段、要素数、坐标系），你确认无误**再**执行写操作。
4. **需要活动视图**：`get_current_map`、`get_layers` 这类"当前地图"操作在**没有打开地图视图**时不会成功 —— 先在 Pro 里打开地图。
5. **中文、空格、长路径**都支持；路径里有空格请用引号。
6. **长任务**：大表/大体量栅格（例如十几万行、上千兆栅格）耗时会明显变长，客户端可能显示等待，不要中途关 Pro。
7. **错误码**：报错一般带错误码，常见的有
   `LAYER_NOT_FOUND`（图层名写错）、`INVALID_ARGUMENT`（参数不合法）、`OUTPUT_EXISTS`（输出已存在）、
   `PATH_ESCAPE_REJECTED`（路径越界被安全策略拒绝）、`ARCGIS_PRO_RUNNING`（有写事务时 Pro 在运行）。
8. **不要**在 Pro 里手工改同一个图层的同时让 AI 去改它（可能冲突）；改完一处再做下一处。

## 9. 数据文件夹工作流（D-073 新增 · 把「文件夹里的数据」自动装载并按你的要求处理）

> 一句话：**数据放在文件夹里 → 告诉它你想怎么处理 → 它先给你看计划 → 你确认 → 它分片执行 → 给你逐项报告。**
> 新增 5 个工具（工具面 149 → **154**＝**历史时点数字，非现值**；错误码仍 **33** 不变；现值见文首历史时点声明）。

### 9.1 五个工具各自干什么

| 工具 | 干什么 | 写/读 |
|---|---|---|
| `scan_data_folder` | 扫一个文件夹 → 可处理清单（名称/类型/几何/坐标系/要素或行数/大小/可用性/建议动作/跳过原因） | **只读** |
| `load_folder_data` | 把清单里的数据（子集或全部）装到**你指定的目标**：建层入图 / 复制入库 / 仅注册连接 | 写（需确认） |
| `apply_processing_plan` | 按**结构化计划**（步骤数组）对目标集合逐个处理；**分片**执行、可续跑 | 写（需确认） |
| `get_job_status` | 任务进度（总项/已完成/失败/跳过/当前分片/剩余/断点） | **只读** |
| `get_job_report` | 逐项报告（处理了什么/跳过什么及原因/失败什么及错误码/产物路径与 SHA256/审计关联） | **只读** |

### 9.2 用法示例（口述 → 计划回显 → 执行 → 报告）

**① 先扫一下文件夹（只读，随时可做）**

> 你：帮我看看 `D:\data\我的数据` 里有什么能处理的。

调用 `scan_data_folder`：

```json
{ "folderPath": "D:\data\我的数据", "maxDepth": 2 }
```

返回清单（每项含 `kind` / `geometryType` / `spatialReference` / `featureOrRowCount` / `available` / `suggestedAction` / `skipReason`）。
**读不了的会如实写出原因，不会静默丢掉。**

**② 装载到工程（先看计划，再确认）**

> 你：把 points.shp 加载到当前地图，再复制一份到 `D:\data\工作.gdb`。

第一次调用**不带 `confirm`** ⇒ 它只回显**结构化计划**（不执行）：

```json
{ "folderPath": "D:\data\我的数据", "items": ["points.shp"],
  "outputMode": "into_map", "dryRun": true }
```

确认无误后再执行：

```json
{ "folderPath": "D:\data\我的数据", "items": ["points.shp"],
  "outputMode": "into_map", "confirm": true, "dryRun": false }
```

`outputMode` 三种：`into_map`（建层入图）／`copy_to_gdb`（复制入库，需 `targetGdb`）／`register_only`（仅注册连接）。
**幂等**：目标已存在 ⇒ 跳过并在结果里写明（不会重复写）。

**③ 按你的要求处理（矢量 + 栅格 + 出图一次说清）**

> 你：把 points.shp 投影成 3857、用 polygons.shp 裁一下、导出一份 CSV；再把 sample.tif 裁一块；最后给我一张当前地图的 PNG 和一份布局 PDF。

调用 `apply_processing_plan`（`dryRun` 缺省 true ⇒ 先回显计划）：

```json
{
  "plan": { "steps": [
    { "tool": "project",      "args": { "inputPath": "…\points.shp",  "outputPath": "…\points_3857.shp", "targetSpatialReference": 3857 } },
    { "tool": "clip",         "args": { "inputPath": "…\points_3857.shp", "clipPath": "…\polygons.shp", "outputPath": "…\points_clip.shp" } },
    { "tool": "export_table", "args": { "inputPath": "…\points_clip.shp", "outputPath": "…\points_clip.csv" } }
  ] },
  "targets": ["…\points.shp"],
  "outputLocation": "D:\data\输出",
  "dryRun": true
}
```

确认后 `"confirm": true, "dryRun": false` 执行；**栅格**用 `raster_clip`，**出图**用 `export_map_view`（回图 PNG）／`export_layout_pdf`（布局 PDF）。

**④ 看进度与逐项报告**

```json
{ "jobId": "我的任务-1" }
```

- `get_job_status`：总项/已完成/失败/跳过/当前分片/剩余/断点（**可续跑**）。
- `get_job_report`：逐项结果 + **产物路径与 SHA256** + 审计关联；**失败会给出原因与错误码，不会静默**。

### 9.4 响应新增字段（D-079 起）

> 以下字段为**响应增补**（仅新增，不改参数面/契约语义/错误码）：

| 字段 | 出现位置 | 语义 |
|---|---|---|
| `ambiguities` | `load_folder_data` / `apply_processing_plan` 的 `dryRun` 计划回显 | **口述→计划的歧义清单**（目标位置／输出命名／覆盖策略／分片／job 身份），便于确认前消歧 |
| `defaults` | 同上 | 你**未指定项**的缺省值（`confirm=false`／`dryRun=true`／`continueOnError=false`／`shardSeconds=25`／`maxItemsPerShard=10`／`onConflict=fail` 等） |
| `countBasis` | `scan_data_folder` 逐项 | 行数/要素数的**来源**（dbf-header／csv-lines／raster-cells 等） |
| `countUnavailableReason` | `scan_data_folder` 逐项 | 计数**不可得时的原因**（不再裸 `null`） |
| `members` / `memberCap` / `membersTruncated` | `scan_data_folder`（`.gdb`） | GDB 内成员摘要（限深 1／上限 50／截断标注） |
| `resumedSkips` | `apply_processing_plan` | **续跑时跳过（已完成项不重跑）的项数** |

示例（计划回显片段）：

```json
{ "dryRun": true, "executed": false,
  "plan": { "defaults": { "confirm": false, "dryRun": true, "onConflict": "fail" },
            "ambiguities": ["target-location: mapName omitted ⇒ defaults to the CURRENT map"] } }
```

### 9.3 三条硬规矩（请记住）

1. **先计划后执行**：`load_folder_data` / `apply_processing_plan` 的 `dryRun` **缺省 true**、`confirm` **缺省拒**；不给你看计划就不会动手。
2. **源数据不动**：默认全程**只读**，结果只写到**你指定的位置**；就地修改需要显式声明且缺省不开放。
3. **分片与留证**：大任务自动分片（每片有时限），断点落盘、可续跑；每项都有前后照与审计记录。
