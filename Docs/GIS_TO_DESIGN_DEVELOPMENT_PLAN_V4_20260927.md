1. 把能力、数据、计划、作业、产物、设计、绑定、证据八种契约提前冻结，避免工具增多后彼此不兼容。

7. 保留“功能全验收→最后做统一安装器/包→实包部署验收”的顺序。

## 8. 试验矩阵与可衡量的完成标准

### 8.1 工具与合同级

每新增工具有正例、关键负例与目标运行证据；文件/状态/数据写覆盖缺确认、只读、受保护路径、输出存在、取消及失败副作用。宿主无关工具做真实集成测试，不为了凑证据假称GIS LIVE。

每模块均有独立验收样例，见模块设计。字段/方法名、模板节点不要求机械一对一单测；风险路径和公开承诺必须有证据。

### 8.2 系统级故障矩阵

| 故障注入点 | 应有行为 |
|---|---|
| 计划通过后源数据被编辑 | 输入检查失败或重新编译，不用旧批准静默执行新输入 |
| 写意图落盘后进程退出 | 恢复看到未完成意图，先核对宿主与产物 |
| GP成功后回执未保存 | 不默认重跑；检查实际输出并标证据充分程度 |
| PS忙/关闭/重启 | GIS阶段仍有记录；设计任务等待/失败可解释；不强杀用户进程 |
| PS保存成功但通信中断 | 查文件/文档版本与已知requestId，不重复创建/修改母版 |
| 磁盘满/无权写断点 | 明确持久化失败，停止依赖可靠恢复的新副作用 |
| 人工改了受控像素 | 检测到或标无法判定的冲突；不得仅靠属性没变就覆盖 |
| 手工改了User_Custom | 非冲突内容100%保留；记录验证方式 |
| 只读模式中途启用 | 后续写步骤拒绝；已在宿主执行的操作如实取消/对账 |
| 升级读旧checkpoint | 可读/显式迁移/明确拒绝之一，不损旧文件，不擅自夺所有者 |

### 8.3 场景、视觉与对标级

- 24核心×至少3轮＋5隐藏变体；每次冻结输入、模型/提示预算、主程序/许可、计时起止。整体完成率目标≥95%，核心正确性/数据保护无阻断失败。
- 30配方全部有通过证据，20模板每套至少2种真实输入；上述覆盖不能被24核心用例替代。
- 对标共同任务：成功率不低于最佳对照；人工操作中位数减少≥30%、端到端中位时间减少≥20%作为目标，达不达如实报告；附失败样本/分布，避免小样本漂亮平均数。
- 3D/遥感/云服务等如双方条件不同，单列，不混入公平性能结论。开放脚本理论表达力不与受控白名单数比较。
- 语义、结构、视觉三层都通过。PSD能打开不等于地图正确；图像像素相似不等于分析正确；接口返回success不等于文件完整。
- 至少5用户试测首次、改稿、更新；这是设计改进依据，不足以支撑普遍统计宣传。

## 9. 每批开发与验收的顺序

1. **准备**：复核唯一ACTIVE、文件所有者、依赖、当前基线、输出路径和授权；冻结本批工具/参数/支持环境/允许变更面。
2. **设计**：补逐工具输入输出、状态/错误、宿主API依据和未决项；先做必要技术试验，不伪造API名称。
3. **实现**：薄工具→公共服务→Host适配；同时做UI、样例与文档，禁止留下多个业务执行入口。
4. **本地验证**：有意义的单元/集成/契约与旧行为回归；遵守既有构建环境纪律，不清种子、不在C盘落物。
5. **真实验证**：用拥有的fixture跑目标宿主、异常恢复和实际渲染，分开记录build/runtime/E2E；真实写入按工单授权执行。
6. **交付候选**：变更清单、数量账、evidence-index、原始结果、版本/哈希、未验证项和恢复说明，状态仅PASS CANDIDATE。
7. **独立验收**：验收者选关键正负例复算，分歧返回修复或由用户裁定；通过后才能更新对应范围基线。

发现新缺陷先判断是否本批范围；不得把新失败自动归为旧环境失败。恢复、删除测试产物只能处理可证拥有对象，未知锁或用户编辑不能清掉。
