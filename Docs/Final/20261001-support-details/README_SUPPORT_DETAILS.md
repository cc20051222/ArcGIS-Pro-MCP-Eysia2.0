## 1. 本次明确的产品区别

| 用户情境 | 目标行为 | 实现依据 |
|---|---|---|
| 不知道哪种资料够用 | 根据目标成果反查缺少的字段、方法、软件与许可，说明影响 | TaskReadinessReport 绑定 OutputContract 和步骤需求 |
| 模型断网/收费不可用 | 已批准的确定性步骤继续；已验标准任务可改用表单 | 模型提案状态与 GIS 作业状态分开，不重复执行 |
| 换电脑/旧版 Pro/换 PS | 显示该任务的具体可用范围与缺项，保留旧成果 | 环境能力快照、版本化支持条目、依赖锁与重新核查 |
| 格式转换会丢字段或精度 | 先显示 LossReport，再按采用合同处理，结果按内容验 | 格式×动作×版本×参数域的独立支持记录 |
| 使用行业任务/规范/模板包 | 导入先检验，不执行动作；采用后固定版本 | 声明式资源包、正负例、来源和依赖核验 |
| 无 PS 或字体缺失 | 明确缺少哪个必要成果；允许领取已验部分或选择不同合同 | 不把 GIS 模式冒充完整 PS 链，不用缺字成果假报完成 |

这些是拟实现的行为，不是现有产品已经提供。目标是减少普通用户的技术判断和无效尝试，并使功能与限制可以直接查到。

## 4. 和开发计划的对应关系

本包细分 WI06–10、WI15、WI22–23、WI26–28、WI30 的模型、兼容、资源包、格式与 UI 工作；与 U/I/R/GA 既有工作池去重。标准任务表单、模型 adapter、完整格式动作和领域资源内容均需逐项实现/验，不视为写出 JSON 即完成。

顺序保持：可靠执行与对账 → 数据/方法与已验标准链 → 真实 PS/办公交付 → 全量 GP 与格式/领域覆盖 → 智能/新手/竞争实测。全量 GP 的 ≥max(2100,ceil(1.1N)) 数量门和逐操作质量门都保留，元数据发现、模型接口数和表单数不替代它们。

仍可保持插件形式与后续统一一键安装。**本方案全部功能、数量、科学质量和体验门通过后才制作最终统一一键包**，再验真实包首装/升级/恢复/卸载/首次成图。本轮没有安装依赖、下载模型、写凭据或制作包。
