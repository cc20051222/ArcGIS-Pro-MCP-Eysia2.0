## 2. 本次新增的五个落地点

| 深化 | 如何实现 | 使用者能感受到什么 |
|---|---|---|
| 数据充分性 | DatasetContract + DataAdequacyReport，把问题所需条件逐项匹配 | 先看到“缺什么、影响哪个指标”，少做无效分析 |
| 数值和解释同源 | TypedFactCell + DecisionRecord + ClaimBinding | 点击图表数字可查原值、分母、方法、来源；图/PPT/表不串数 |
| 可恢复执行 | 持久执行确认、步骤状态、效果对账、代际隔离 | 中断后提示可复用和待对账部分，不重复写、不假报完成 |
| 可预测更新 | 依赖指纹 + UpdateImpactPlan + 候选交付版本 | 换人口、期次或规范前可看到需重算范围；旧成果保留 |
| 零 PS 手工设计 | 真实 Adobe 命令、宿主单写、语义图层、测量与有限自动修复 | 普通任务直接得到预览和可编辑母版；不要求用户学 PS |

以上是目标行为。普通用户只负责选择资料、确认关键业务口径、批准显示的输出范围、选择或修改预览；设计、制图、文件生成与检查由系统执行。专业方法、规则与模板的维护由资源包作者在开发/验收时完成。

## 3. 用户操作流程

1. 拖入文件夹、选择当前工程对象，或选择一个已验行业任务。系统发现数据并显示任务范围。
2. 说出目的，例如“比较两个设施方案，生成汇报图、指标表和 PPT”。系统先检查数据充分性和方法条件。
3. 在一张任务卡确认关键口径、精确输出目录、必要文件、执行范围和预算。已有授权被继承；新增或越界内容才要求补充决定。
4. 系统执行分析、同源指标、GIS 素材、PS 排版、办公文件和检查。任务卡区分执行进度、验证进度、等待原因与可领取的部分成果。
5. 查看最多三张首轮预览。说“图例大一点”“换成横版”，系统先解释影响范围，再按已批准边界生成新版本；方法或指标改变重新预检。
6. 必需文件全部通过后交付；以后替换资料，先显示更新影响，再生成新版本。用户无需在 PS 里逐层操作。

标准输入的目标是集中解决关键问题；问题数并非硬性上限。关键条件仍未知时不能为减少提问而猜测。第一次软件配置、业务确认、异常处置分别统计，不混入“零 PS 手工设计”。

## 5. 不变的开发与发行要求

架构保持 Shared 无 SDK、MCT 调度、Composition 唯一注册、配置集中、回环端点、受限 Bridge 和固定命令；模型不能产生任意可执行脚本。公开参数/响应/错误码/白名单变更走现有 SC 裁定，内部草案不能直接进入公开 schema。

本包 30 个工作项是既有 U/I/R/GA 的细分，需与现有工作池去重，**不是额外 30 个工具、不是已派工、不是增加后的固定工期承诺**。WBS 估算和专业内容/逐操作验证成本仍以 V2 为起点，再依据切片实绩修订。

最终仍是插件形式：ArcGIS Pro 插件 + 受控 Photoshop UXP 插件 + 已验资源包，后续可由统一安装器协调。具体 Adobe 分发/加载方式须按支持版本和官方机制真机验证。**全部功能与量质体验门通过后，才制作本方案的最终统一一键包**；历史包和既有发行链按其原范围区分。本轮没有制作安装包。
