# ArcGIS Pro MCP：自动化优先开发与验收计划 V5

日期：2026-09-27。状态：**规划交付，未启动产品实现、真实安装或制包**。

新增首要约束：目标用户不会使用PS，人工设计很少。因此默认完整路径必须由系统自动完成制图、美化、检查、修正和导出；用户只需表达用途、确认业务方法、可选改稿和取用成果。

配套：[V5产品创新方案](GIS_TO_DESIGN_AUTOMATION_STRATEGY_V5_20260927.md)、[V5实现设计](GIS_TO_DESIGN_AUTOMATION_IMPLEMENTATION_V5_20260927.md)。V4无冲突的GIS、安全和数据保护细则继续适用；默认用户流程、自动化优先级与完成门以V5为准。现役工单和治理不由本计划修改。

## 1. 基线与范围

本轮静态复算：Composition注册调用154、错误码常量33、GP白名单53。未重验安装位、运行位、包身份或LIVE，不推动基线。D-079工单文件仍标ACTIVE，正式新开发需其派单方裁定/移交。

内部自动设计服务A01–A10和本计划Z工作包不计工具数。PS细粒度工具服务于系统自动执行，仍保留规划；用户不会PS不是删除后台能力的理由。对标Q-DELTA另列真正缺口、数量、成本和证据，未补齐不宣称全面领先。

全部内容为建议；不擅自分配D/C/G编号、不另开ACTIVE、不修改现役ledger。执行只交PASS CANDIDATE，最终由独立验收方裁定。

## 2. 改变投入重点

| 优先级 | 工作 | 原因 |
|---|---|---|
| P0 | 自动成果需求、模板选择、约束排版、真实预览、检查修正、自动导出 | 用户不具备后续手工补救能力，必须首波闭环 |
| P0 | 专业地图正确、数据/来源、只读/权限、故障恢复、原件保护 | 自动化越多，错误更不能依赖用户发现 |
| P1 | 自然语言/快捷修改、意图版本、项目风格、换数据自动重渲染 | 大幅减少重复操作，形成日常使用价值 |
| P1 | 多尺寸重排、批量一致性、密集图例和复杂版式 | 从演示走向真实工作 |
| P2 | 外部手工PSD的细粒度自动合并、高级专家图层交互 | 用于少量专家；原件检测/保护和另存新版仍是P0 |

P0/P1/P2是产品优先级，不等同于缺陷严重度。保留原工具规划的数量和专业深度；把自动服务提前实现，把专家合并复杂度从默认流程移出。

## 8. 新版验收：机器检查、专业审阅、新手试用三条线

### 8.1 数量和基准

- 基础工具总账154＋21＋35＋30＝240；新增86分16批，每批≤8；自动服务、内部步骤、模板不能重复计入。
- 24核心任务×至少3轮＋5隐藏变体继续执行，涉及分析/更新/取消等真实工作；30配方各有完整支持证据，不能用模板图件代替任务功能验证。
- 20模板×3种标准输入＝60样例，覆盖普通、较密集/较长文字、不同研究区/页面条件；每种模板具体输入和支持前提在F05冻结。
- 压力集另至少20例，包含极长标题、密集图例、多图框、字体变化、连续改稿等；明确无解/不支持输入的正确拒绝测试单列，不能把它们计为成图成功。

### 8.2 自动化指标与口径

| 指标 | 计算方法 | 目标/完成要求 |
|---|---|---|
| 标准自动完成率 | 满足事前冻结条件且成功产出通过检查的标准任务数/全部60标准任务 | 发布前60/60，最多2轮自动修正，无PS人工编辑 |
| 首轮无需修正率 | 首次真实渲染即通过检查的标准任务数/60 | 目标≥90%，呈现实际比例与失败原因 |
| 压力集自动完成率 | 最多2轮修正内完成且质量通过的数量/全部事前确定适用的压力任务 | 目标≥95%；所有失败披露，不影响严重错误零容忍 |
| PS编辑操作数 | 用户手工操作图层/蒙版/字体/排版等次数 | 宣称自动路径为0，任何代操作都计入 |
| 配置与运行摩擦 | 开启PS/启用插件/配对/目录授权/异常恢复次数和时间 | 与设计操作分列；不得藏进“全自动”成绩 |
| 非专业用户完成率 | 无设计师代操作完成预定任务数/分配任务数 | 最终8–12名无PS经验用户，每人至少2任务，目标≥90%；逐个失败列明 |
| 图件质量 | 科学正确性硬检查＋独立专业评分 | 严重语义/数据错误0；盲评按预先冻结维度与阈值 |
| 修改和更新 | 意图修改正确、撤销可用、新数据生成新版且风格保留 | 不靠手动PS编辑；原件保护与副作用对账全通过 |

可用输入/环境条件在测试前冻结，发生断线、保存失败或超时后不能事后把该次移出分母。另报告所有尝试的结果分布（完整、基础GIS、部分完成、阻断、取消、失败）和首轮/重试次数。缺PS时基础图合格不计GIS＋PS链成功。

首次设置无需设计技能但可能有官方权限操作；首次时间单独测，日常生产计时不能偷偷依赖测试人员预先修图。无经验用户试测用于产品验证，8–12人的结果不支撑对全部用户的统计性保证。

### 8.3 专业评阅

由至少两名独立的制图/设计评阅者检查真实最终产物，按冻结量表评阅可读性、信息层级、布局、配色和用途适配；科学正确性单独做硬检查。建议以五分量表均分≥4且无单项低于3作为初始门槛，F05定标后冻结；分歧留记录并裁定。

为了证明自动化效果，评阅者可以指出问题、维护模板/规则，但不得在被计为自动成功的样本上手工修图。开发期专家投入是模板资产与验收工作，不转嫁给最终用户。

AI/视觉模型只作辅助建议，不是唯一验收人；图像相似度不能代替地理/数值准确性，也不能证明“更美观”。

### 8.4 关键异常用例

| 用例 | 必须行为 |
|---|---|
| 所有候选有硬错误 | 明确无合格解，按获准布局/附页修正或停，不交最漂亮的错误图 |
| 修正反复产生同一问题 | 停止循环，保留证据和当前版本 |
| 最终分辨率出现溢出 | 最终复核阻断，剩余预算内修正；不能沿用缩略图通过结论 |
| 用户说“更突出高风险” | 合法强调；涉及过滤/分类/方法变化时澄清，不涂改结果 |
| PS未开/插件未加载 | 引导或等待，状态真实；基础图不冒充完整PS成果 |
| PS忙或有人在编辑 | 不强制抢占/关闭文档；有界重试与可取消 |
| 保存成功回执丢失 | 先对账requestId、文件、文档revision，避免重复写 |
| 外部PSD被改或无法验证 | 保留原件，另存自动新版，不要求普通用户逐层解决冲突 |
| 缺字体/色彩条件 | 仅在批准替代政策内变更并重排，否则明确缺口 |
| 只读开启或批准范围变化 | 后续写拒绝或重新预览；自动修正不构成绕过权限的理由 |
| 宿主退出/磁盘满 | 断点和已完成产物可核对；不自动把缓存切到C盘/TEMP |

## 9. 批次纪律和公共工程工作

每批按：目标与范围→API/契约依据→实现→局部/兼容验证→真实宿主与图件验证→PASS CANDIDATE→独立验收推进。

持续工作包含schema diff、旧断点兼容、入口策略等价、D盘拥有根、工具计数、白名单嵌入资源对齐、诊断脱敏、预览/修正预算、许可和字体/模板来源。

代码分层不变；Current目录目前仅占位，支持版本取实际构件和运行证据；不因同属net6/net8推定所有API可用。新错误原因优先映射33码details，公开结构和语义改变仍需评审。

自动设计失败用明确状态交付：needs_clarification、waiting_engine、quality_blocked、needs_reconcile等是拟议内部状态，外部协议映射需审批。执行者不能自行宣布这些状态替代现有契约。

运行主程序/写GIS/改配置/安装依赖/签名发布仍依实际授权。当前工作区不dotnet clean，不清种子，不动旧仓库与受保护用户资产；清理进程后须复核remaining=0。

## 12. 容量重估

减少用户手工设计会增加自动排版、检测、恢复与模板工程工作，不能据此压缩成“少做几个PS按钮”。专家细粒度合并后移可以抵消部分投入，但不足以免去自动化质量验证。

假设至少1名GIS/C#开发＋1名UXP/前端开发，另有独立QA/制图审阅和产品决策资源；单ACTIVE内允许明确分工，独立验收串行。初步容量范围如下：
