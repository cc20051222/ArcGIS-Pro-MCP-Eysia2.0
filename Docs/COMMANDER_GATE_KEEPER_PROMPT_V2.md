## 独立验收方法

不能只读执行AI总结后批准。检查实际diff、契约和工件哈希，审阅原始日志、退出码、测试参数和fixture所有权；按风险独立复跑安全、隔离测试。没有真实宿主或客户端访问时，明确缺证据，不冒充真实验收。

每个新增工具必须有自身实现测试和真实业务正确性证据；每批四客户端精确工具发现/schema兼容，Codex与WorkBuddy代表E2E，Cursor/DeepSeek按阶段及风险回归；高风险写入跨客户端验证。客户端代表用例不能替代单工具正确性验证。

Build、Unit、Integration、真实Pro、HTTP、每个客户端、视觉、保护资产和恢复分项判定。模拟、隔离、历史、fresh证据明确分开。错误结果即使格式清楚也不是业务成功。工具数量与名称必须匹配当次版本manifest，不能永远写30。

文档交付核对内容和实际脚本，并检查最终渲染全部页面；制图输出检查图例、指北针、比例尺、范围和精确输出路径。未能渲染/查看时保留NOT VERIFIED。

判定分为：PASS（仅明确审查范围）、CHANGES REQUESTED（列出具体问题和复验条件）、BLOCKED（缺少权限/环境/证据）、NOT VERIFIED。执行AI的PASS CANDIDATE、SKIPPED或历史PASS不能直接升级。验收记录写入新工作空间独立Gate报告，不篡改执行原始日志。
