## 3. 用户操作流程

1. 拖入文件夹、选择当前工程对象，或选择一个已验行业任务。系统发现数据并显示任务范围。
2. 说出目的，例如“比较两个设施方案，生成汇报图、指标表和 PPT”。系统先检查数据充分性和方法条件。
3. 在一张任务卡确认关键口径、精确输出目录、必要文件、执行范围和预算。已有授权被继承；新增或越界内容才要求补充决定。
4. 系统执行分析、同源指标、GIS 素材、PS 排版、办公文件和检查。任务卡区分执行进度、验证进度、等待原因与可领取的部分成果。
5. 查看最多三张首轮预览。说“图例大一点”“换成横版”，系统先解释影响范围，再按已批准边界生成新版本；方法或指标改变重新预检。
6. 必需文件全部通过后交付；以后替换资料，先显示更新影响，再生成新版本。用户无需在 PS 里逐层操作。

标准输入的目标是集中解决关键问题；问题数并非硬性上限。关键条件仍未知时不能为减少提问而猜测。第一次软件配置、业务确认、异常处置分别统计，不混入“零 PS 手工设计”。

## 6. V5创新总架构：把一个成果流程变成可持续演进的产品

本版的工程目标是八周开发与验收窗口加四天缓冲，合计60天；它是以真实资源和吞吐校准为前提的目标，不能由五个执行端的数量直接推导完成。原30个WI、285项语义候选范围、20个PS合同、36套模板/108张标准成图、三条业务链、可编辑Office、兼容迁移和最终安装门全部保留。新增自主演进与参考学习是额外边际工作，不能通过删旧项、把待证项改为支持或减少逐操作验收兑现日期。根计划与工期的唯一维护入口为[八周实施与发布计划](<../01_主方案（6份）/IMPLEMENTATION_AND_RELEASE_PLAN.md>)。

产品采用五个协作平面，而不是另起五个独立执行器。数据平面负责InputSnapshot和事实，能力平面负责可信来源、参数合同、逐操作资格和版本，决策平面把任务转成受限typed DAG，成果平面把同版事实变成GIS/PSD/Office，演进平面负责变化发现、偏好与技能候选、回放、候选能力包和兼容激活。五平面共享同一Invoker、根预算、持久执行账本和版本依赖图；没有任何平面可以把模型建议直接变成生产代码、批准或科学事实。

每个根任务绑定一个ExecutionLock：输入快照、方法包、能力包、设计资源包、模型角色配置和输出合同的不可变版本。后台发现新工具或新偏好时可以生成候选，但正在执行的任务继续用原锁。用户明确采用更新时新建任务revision，先展示方法/数据/视觉/资源影响，再进行有依据的复用或重算。这样“自主更新”不等于运行到一半换算法，“学习习惯”不等于未经确认修改业务口径。

### 6.2 十二项新增创新工作的边际成本

新增创新以J01–J12在主方案中统一编号，绑定原WI主责和独立边际工时。这里按能力主题说明，不把主题当作十二个已经实现的工具：可信更新、资格工厂、语义去重、成图风格提取、参考数据结构提取、用户偏好、失败学习、关键缺口与方案探索、科学约束布局、增量更新、技能编译、演进工作台。具体编号与计账以[模块工作池](<MODULE_INTERFACES_AND_BACKLOG.md>)和主计划一致为准。

每项创新必须有可独立验证的输入输出、两个以上反例、回退办法和采用依据。复用原合同的字段或通用codec只计一次公共基座；新的oracle、复杂参数、行业知识、跨版本回放和参考处理仍计增量成本。模型能够拟稿不代表参考标注、许可和真实宿主证据免费。首两周应把这些边际账转成实际工程/专业/验收分钟，任何未知项都不能以零填表。

## 7. 一指挥五执行的实施组织

| 席位 | 唯一主责 | 交付边界 |
|---|---|---|
| C0 | 派单、冻结合同、独立验收和风险/资源决策 | 不写产品码；维护证据索引和验收队列，执行端不自批PASS |
| E1 | WI01–04、WI10：可靠平台、资源和集成 | 同一集成入口；Composition/Configuration短写窗由其协调 |
| E2 | WI11–15、WI30：GP资格、兼容和能力更新 | 不因生成合同而宣布真实资格；逐操作环境和oracle完整 |
| E3 | WI05–09、WI16、WI23、WI27、WI29：数据、决策、事实、学习 | 偏好不改变批准；新方法/规则先候选再独立验收 |
| E4 | WI17–22：设计、PS、Office、交付 | 拥有文档与固定命令；全局modal单写；科学区域不变形 |
| E5 | WI24–26、WI28：三条业务链、行业内容和工作台 | 编公开回归与用户任务；不持有隐藏答案、不裁定自己实现 |

E1–E5在隔离候选目录并行提交，各线最多一个主要在途工作项，公共合同先形成可审差异再集成。五线同时“准备”与同时“真实写宿主”不是同一件事。MCT、共享GP环境、同一GDB、PS全局写、许可和内存都是实际容量约束；预约过期也不证明旧写进程已经停止。新增多个真实Host或软件依赖，需要相应许可与授权，不从计划书自动获得。

C0每天优先验收可靠性与关键依赖，然后审新增能力队列，再审UI和内容。独立oracle在执行前冻结，执行端只收到支持域和测试输入，隐藏答案由C0隔离保管。E5可以准备公开检查器，不能以其测试绿灯替代C0独立裁定。失败和超时留在分母，跨线审查是补充而不是覆盖原验收方。

## 8. 两个月的关键路径与停止条件

第1周完成源码差距复核、合同冻结、可写D盘工作区、Host能力与许可盘点、可信catalog快照以及30–50项分层资格试验准备。第2周把T0可靠执行和真实最小GIS→PS→Office链做成可受验切片，同时测定复杂参数、独立验收和PS写窗的实际成本。T0未过时其余线仍可做纯准备，不能扩大自动写。

第15–42天是四个完整周的GP真实资格窗口。按Q=0保守计算，旧门K=2100需要每周净独立验收525项；扩展到3000项真实去重语义能力需要750项/周。这里“净”指失败、返工、许可等待和C0复核已扣除，不是发现量、生成量或发起量。如果完整冻结比较得到更大的N，门数和吞吐还会提高；已有资格能否复用必须逐件验证其环境和依赖，不能先假定Q>0。

525和750分别只是两个工作池的必要下限，不能把旧GP2100和新增语义3000默认视为同一全集。以可证明共享资格的工作项ID建立交集，`K_union=K_GP+K_sem−K_overlap`。两门取2100与3000、Q_union=0时，完整资格池可在3000至5100之间，对四周净吞吐要求为750至1275项/周；零交集不能仍用750排期。复杂一对多映射、额外支持域和J创新检查的边际成本继续单列，union计数不代表全部工时。真实交集未知时保留区间，不编造重合率。

第3–6周同时深化两旗舰模板、规范建库、用户工作台、参考学习和自主更新的完整负例。第7–8周进行冻结版本的全部功能、隐藏场景、新手、恢复和公平比较验收。所有功能门过后才构建统一安装候选并验证安装/升级/回退/卸载；最后四天只作为已估工作缓冲，不能把未开发的大功能塞进缓冲或取消发行门。

达成八周必须同时证明：关键资源约束DAG可行；GP净吞吐达到目标；C0复核能持续跟上；专业oracle和108张标准图等独立工作已纳入工时；软件/许可/参考权利和固定adapter不存在硬阻断；新增J边际成本没有超出剩余窗口。任何一项未达，就给出实际剩余关键路径和所需资源，继续保留完整范围和质量门。不能同时把范围、质量、资源都固定后把60天说成数学保证。

## 9. 自主更新与自我学习的默认边界

自动化覆盖发现、差异分类、合同候选、合成受限fixture准备、影子回放、证据整理和更新建议；生产激活需要可信来源、既定批准范围及独立接受。新类型、未知effects、未验许可或不可解释oracle进入待证队列，生产policy、白名单和执行代码不自动放宽。固定provider adapter使用统一Invoker和已审Host；禁止自由脚本、第二注册表、自动安装未知插件或凭据扫描。

学习库存四种不同对象：明确保存的偏好、已验可回放技能、可复现失败案例、已验能力版本。临时指令优先于个人偏好，项目约束优先于泛化推荐，科学事实和安全执行门优先于任何偏好。用户可以查看一条推荐的来源，停用某种学习、删除偏好、撤销项目参考授权并恢复前一可用资源版本；历史交付证据仍按其归档要求保留，不把撤销偏好伪装成删除必要审计。

“长期领先”应表现为可持续测量的能力增长和质量稳定：每次版本冻结比较语义覆盖、完整任务成功率、同源事实、人工设计时间、端到端耗时与恢复成功。没有可证明的永久竞争优势；本方案建设的是主动发现差距、快速适配和可靠采用的机制。下一次竞品、Host或用户资料变化会产生新的diff，而不是沿用一次胜出结论永久宣称领先。

开发先把每件交付物的反例跑通，再扩大规模。一个DTO生成成功不证明ProviderIR完整；一种codec绿灯不证明其工具全集；一张fallback好图不证明参考学习实现；一次恢复截图不证明跨Host恰好一次。证据状态只依据实际支持域、真实原始记录与独立接受推进。

### 12.1 最短集成闭环

每个受验候选锁定`ProviderIRDigest→CodecPlanDigest→PreparedInvocation→ExecutionEvents→ArtifactManifest→OracleSpec→EvidenceRow→AcceptanceBundle`。纯准备环节可以并行；有副作用环节依十闸门和真实资源约束。节点输出是精确immutable引用，不传“最新结果”；多个节点共享同一稳定logicalOperationId和当前fence，没有第二Invoker。

首个闭环选取带复杂参数/原位或派生风险的代表操作，配正例、缺条件负例、intent失败、receipt丢失和Host重启五类观测。该闭环证明公共基座，不替代每操作首次资格。继而在同受验payload下扩大分层资格，错误行隔离仍留分母；E1统一集成，C0只接受对应payload，E2继续准备下一批不能改掉待审目录。

## 13. 60天可行性不是倒排，而是有限容量证明

V5采用资源约束依赖图预测，而不以AI数量除工期。每个节点含工程分钟、专业/oracle分钟、实际Host占用、独立复核、返工分布、前置、可并行准备部分和必须串行的资源。测量没有获得时值是UNKNOWN；即使已有规范ID，也不能假设oracle、语义去重与复杂参数差异免费。

首两周的可行性包至少给出：可信全集与许可证可达性；两池交集的逐行证明；30–50项困难分层操作的完整准备/正负例/对账/复核耗时；PS最小真实写和保存重开占用；参考解析失败退模板的完整任务时间；C0非GP验收容量；新增J的剩余边际量。小样本均值用于敏感性估计，不声称直接证得四周持续750–1275净项/周；持续吞吐仍须实际完整窗口验证。

排程算法与容量算式见[模块接口与工作池](<MODULE_INTERFACES_AND_BACKLOG.md>)，锁和证据结构见[领域合同](<DOMAIN_CONTRACTS_AND_STATE_MACHINES.md>)。只有资源有限DAG日历能覆盖全部原门与新增采用门，才保留60天目标；不能把未支持参数、参考学习或难行业项删除。许可、可信方法全集、独立oracle或单Host容量硬阻断时，自动调度只能解释并优化剩余工作，不能凭空解除阻断。

V5最终交付仍含原全部范围、独立资格、36模板/108图、三链、可编辑Office、兼容恢复、新手和隐藏门；功能门全部通过后才制作与验收统一一键包。此版本增强可实现性和可检验性，仍是规划候选。

## 14. V6增量实现路径与交付顺序

保持现有插件/Shared/Invoker/JobStore；V6在原DC/模块内增加子记录，不建立平行执行框架。E3先编译PredicateGraph与ScenarioSpec，E1先持久AttemptToken/StopIntent/资源lane，E4将真实PS调用和交付激活接同一合同，E2让资格失效与余期计算消费真实记录，E5提供公开对照与mutation。E1唯一集成，C0不代写产品。
