## 1. 用户得到什么

普通用户不需要掌握GP工具名称，也不需要手工Photoshop设计。用户提供资料、选择用途和必要口径，系统完成数据理解、合法方法选择、GIS分析、制图、自动PS美化、可编辑Office、完整交付、后续更新与恢复。用户可以提交参考成图、合法数据集或现有项目，让系统学习其视觉偏好、资料映射和常用操作；科学事实与视觉风格始终分离。

“更加智能”表现为减少重复解释、主动发现真正缺失的资料、从用户采用的改稿学习、自动寻找已验证的可行方法、能够说明为什么复用或重算、能恢复未知结果而非重复写入。用户的显式选择优先于历史习惯，行业规范和科学约束优先于审美偏好。参考图中的文字、坐标、数值、统计结论不会成为本项目事实来源。

| 用户动作 | 目标体验 | 工程实现 | 必须保持的限制 |
|---|---|---|---|
| 第一次提供资料 | 系统列出真正缺项及对成果的影响，集中问必要问题 | DatasetProfile＋DataAdequacyReport＋TaskReadinessReport | 不因减少提问而猜CRS、分母、时相或方法 |
| 上传参考成图 | 提取布局、色彩、字号层级、纹理与留白，给出可比较候选 | ReferenceStyleDNA＋DesignSpec编译＋保护区域检查 | 像素不能直接恢复可靠GIS几何或可编辑原图层 |

## 2. 支持架构：一份事实源，多种用户投影

`CapabilitySupportManifest`是统一支持信息源。工具目录、参数表单、任务预检、帮助、学习进度、支持列表、兼容提示和发布矩阵都由它投影。模型不维护另一份工具能力真值；GUI不靠描述文案决定成功；资源包作者不可以自行宣布本机资格通过。

所有执行维持既定分层：`AI Client → MCP Transport → MCP Protocol → MCP Server → Tool Router → Tool Registry → GIS Tool → IArcGISHost → ArcGIS Services → ArcGIS Pro SDK`。唯一注册中心为`Composition.BuildRegistry()`，共享层不得引入SDK，SDK访问走`QueuedTask.Run`，配置归集中模块。MCP仍受控于`127.0.0.1:6520/mcp`；现有6511桥只接纳固定类型化操作，不新增任意Python、JS、Shell或旁路端口。

支持服务分为六个相互约束的部分：

1. **能力与环境事实**：记录宿主、实际插件/桥、许可、模型、字体、格式、资源和证据域；当前缺口与开发成熟度分开。
2. **任务准备与合法执行**：将表单、自然语言、技能和资源包编译为同一类型化计划，经过同一准备、批准、预算、Invoker、结果检查和回执。
3. **学习资产**：把用户反馈、参考样式、资料映射与已验案例存为可导出、可忘记、可解释的版本资产；不默认训练新大模型。
4. **自主适配流水线**：发现差异、生成声明式候选、沙箱资格、独立验收和采用；可以自动工作但不能自批生效。
5. **持续观测与回退**：用CompatCanary和漂移事件检查真实环境变化，撤销相关资格，保留旧任务依据与成果。
6. **工作台与交接**：将真实状态呈现为用户能理解的业务阶段，让普通用户直接领取、比较、改稿和更新。

## 4. 完整范围和不缩水的分母

原20公共模块、八领域、12个U产品服务、20个PS动作、36模板/108图、60场景、21输入格式/来源族与105候选动作格都保留。285是原语义候选底册，不能写成285已实现；内部服务和学习对象不重复计作GP。行业入口换名字、别名、参数组合与配方都不增加独立工具数。

GP目标是冻结可比条件后，以去重且真实可执行的核心操作数量达到`K=max(2100,ceil(1.10×N))`，N为比较对象在冻结版本、许可、输入与参数域下的可比操作数量。1900+不是1900整值。自主增长必须继续逐操作维护方法前提、参数依赖、effects、许可、oracle、恢复策略与证据；同一Esri工具全集本身存在数量上界，超过它需要新增真正独立的合法算法来源与产品能力，不能靠重命名制造断档。

每个正式承诺的格式动作和实际输出逐项保留。GIS PDF/SVG/EPS不能用PS栅格图代替；PSD/PSB需保存后关闭重开；DOCX/XLSX/PPTX需验证承诺部分的原生可编辑性；100页图册需核验漏页/重复与系列一致；HTML需要真实交互和离线资源，不以截图代替。缺依赖的动作保持具体阻断，不把静默功能开关视为完成。

学习和新创新同时有成功、失败、越界和漂移用例。原科学错误为0、事实绑定100%、错误对象写入0，108图首次自动达标至少98/108且不得用PS手工补设计，最多两次已批准自动修正等门不下降。用户习惯不能改网络分析为直线距离，不能改科研显著性/分母/分类阈值，不能为了模仿别人图的好看而污染事实。

## 5. 全自动学习的边界与工作流

首版默认采用检索、明确反馈、验证过的案例与受限规则，不要求训练一个新基础大模型。模型可建议新偏好或配方，但候选经过规则检查、有限试验和采用；训练/微调可作为有资源条件的后续技术路径，但其首版必需业务效果须用检索与固定编译实现，不能把学习功能推迟或删掉。

完整闭环为：`事件采集 → 去敏与范围归属 → 学习候选 → 冲突/科学/许可检查 → 有界验证 → 用户或政策采用 → 小范围观测 → 升级/忘记/撤销`。每个环节记录版本和来源。学习不等于保留全部聊天；只收集实现用途所必需的事件，用户可选择关闭、导出、删除或重置项目偏好。关闭学习不影响已有普通任务能力。

参考图学习先定位地图、图例、标题、比例尺、说明与装饰区域，再把可借鉴的视觉参数转成受限样式。上传数据集的语义分析独立进行；是否可把数据用于本项目分析，是否可复用图片素材，是否可向远端模型发送，是否可作为未来训练资料，必须分别决定。参考文件不能携带执行权限；其文字不能成为系统或派单指令。

系统可以从多份参考总结风格交集与差异，为用户生成最多三张首轮比较预览。采用的预览及明确改稿反馈可以更新PreferenceProfile；未采用图不成为稳定偏好。参考风格与科学规则冲突时展示具体冲突和合法替代，例如保留分类颜色但借鉴排版，不提出伪造数值的“视觉优化”。

**资格池不能假定两个门完全重合。** 旧GP门为`K_GP=max(2100,ceil(11×N_GP/10))`，新独立业务语义挑战为`K_sem=max(3000,ceil(3×N_sem/2))`。总去重资格池为`K_union=K_GP+K_sem−K_overlap`，交集K_overlap必须逐项证明，不能靠名称或推测抵扣；当前可复用Q_union也要在同一并集口径核证。四周所需净率为`ceil((K_union−Q_union)/4)`。在2100和3000、Q_union=0的示例下，750/周只对应交集2100、并集3000的下限；零交集时并集5100，需1275/周。模型、格式、模板与用户等其他门的审核资源仍另外预约，不能塞入该操作数量率假设。

## 7. 减少等待而不减少验证

把支持合同生成工作台、参数表单、测试索引和帮助，减少重复维护。格式与GP按共用codec家族复用解析，再对每项方法前提、effects和oracle做独立验证。模型每次只取相关候选的完整schema和必要事实，不把2100全集塞进每轮上下文；所有必要约束保留。布局预备、Office规格、资源索引可以纯计算并行，PS写入按全局modal和文档归属串行。

不可变资产缓存具有严格依赖指纹。数据、CRS/变换、单位/选择、方法、模型权重、随机种子、规则、encoder、字体/ICC等变化形成相应重算闭包。只有oracle/验证准则变化且分析/事实/渲染依赖完全不变，才可对既有不可变资产先重验；不能把方法规则变化误判成只检查。真实当前写入仍要durable intent、fence、派发前复核和结果对账，cache命中不能复用旧批准。

支持服务维护三类预算：任务的时间/费用/内存/产物预算，更新/学习候选的试验预算，持续监测的后台预算。后台任务不可饿死用户当前计算、取消和状态读取。网络超时、PS掉线、未知effects、usage未知都保留对账状态，不盲目重发，不以快速失败计性能成功。

## 8. 用户体验与验收证据

用户工作台围绕“资料与条件、执行与检查、预览与交付、学习与更新”组织。技术术语映射为具体信息：正在学哪份参考、已采用哪些习惯、哪一个新工具等待资格、缺哪个字体、哪些数据将被发送、为什么这一轮重算。不要要求普通用户理解codec、fence或缓存键；诊断可展开供支持人员查看。

证据账本记录具体版本、输入、任务、参数域、环境、执行及独立检查。阶段名称只有在对应动作真实发生后更新。未知TFM、模型能力、GPU/内存或格式损失显示UNKNOWN及原因，不能填0或假定支持。静态JSON、模拟事件、结构通过不能证明真实GP、PS、Office、模型或用户完成。

## 11. 一条普通用户真实流程与恢复分叉

**先检查条件，再给受约束任务卡。** 用户打开任务入口后，系统只读获取实际Pro/PS/模型、当前许可与资料，分开报告缺软件、缺许可、没探测到、尚未逐项资格。用户不先填写数百参数，也不在等待半小时后才知道缺许可。实际probe不能猜硬件或暗中checkout许可；必要写探针与资格作业另走已批准拥有范围。

**绑定数据，再采用参考用途。** 用户选自己的数据和可选参考图/数据集，分别选择只学风格、学数据组织、当前数据输入或指定素材复用。系统提取ReferenceStyleDNA/DatasetProfile候选，展示可确定和不确定部分；不存在的图层、错误比例、未知字体或看不清的文字不能伪造为确定结果。像素图不能保证100%复制，也不能提供可靠可编辑GIS几何。

**任务卡冻结事实和必要成果。** 卡片包含对象、用途、方法允许集、单位/分母/时相、必要文件、精确输出目录、环境与成本缺口、参考作用和已采用偏好。普通用户只决定业务关键项，不负责审阅内部代码。任务卡与当次准备共享同一版本，环境在等待中变化时更新状态而不静默扩大effects。

**可解释的等价模板回退。** 若参考风格置信不足，系统在相同OutputContract、事实、内容、尺寸/DPI和编辑性条件下选择已验模板生成候选。能保持所有必要功能才叫等价回退；缺PS许可不能用PNG冒充PSD，缺科学方法不能换成另一问题，丢图例或原生Office不能称模板降级成功。找不到完整等价路径就具体等待，不以部分结果报全功能。

**真实生成和保存重开。** 已批准步骤经统一Invoker，PS写单lane、固定命令、逐动作读回，保存后关闭重开；Office实际打开并核可编辑性。文件存在、模型说完成、schema正确都不是成功。未知效果先对账，用户可领取明确已验部分，完整revision只有全部必要文件成立才激活。

**改稿和学习可以解释、纠正和遗忘。** 用户说“图例大一点”“以后不要浓色”，系统显示影响仅样式还是数据/方法，列出这次使用哪条参考/偏好；一次改稿只改变本次，明确记住才进入稳定偏好。用户可撤销参考、暂停学习、纠正映射或忘记偏好。忘记不改写历史科学事实，已经领到的旧版保留。

## 12. 支持深度：统一字段只是起点

将Host、模型、格式、模板、能力包都映射到相同字段，能减少表单和支持文档重复，但不能靠大家共用`id/version/schema`就宣称通用支持。每格式仍逐READ/WRITE_NEW/QUERY/EDIT_OWNED/ROUND_TRIP验证实际语义和损失；每模型路径仍真实处理拒绝/流/usage/取消；每PS动作和输出仍保存重开；21族105候选动作与55条旧支持规格全部在工作池。

支持成熟度和当前可用性分开。“保留该功能”是研发和发行范围不删除，**不表示任何Host、任何许可和任何软件缺失的机器都能执行**。产品必须声明参考环境、实际支持域、依赖和当前缺口，并使工作台/任务卡/发布矩阵一致。当前缺许可可以保留历史资格，当前可用性仍UNAVAILABLE或CONDITIONAL，原因另字段；不能借功能保留把环境失败记为成功。

## 13. V5新增成本与可行性退出门

新增SupportProbePlan、风格不确定度、等价回退证明、学习Run索引、资源包差分矩阵和签名/许可核查都计入原30WI及J01–12边际，不额外创建“免费创新线”。开源机制借鉴降低重复设计，不自动降低真实Host、专业oracle、用户和独立验收工时；六席、合法许可、525单门下限及750–1275并集吞吐条件仍未证明。

W1–2采用前至少验证：一个缺许可任务能在执行前准确定位，一个有不确定区域的参考可生成合法完整候选且差异可解释，一个离线包可在无网络的真实依赖条件下完成，一个保存回复丢失任务先对账而不重写，一个忘记事件在重启后仍停止使用对应偏好。它们是可行性探针，不替代全量门。

若未达原科学/编辑性/格式/功能要求，优化保持候选，指出需要哪一实际资源或固定adapter；不能以“AI以后会学会”把必需能力从首版挪走。8周和4天缓冲继续是有前提的目标，不把兼容矩阵、模板回退或引入社区名词等同为周期已经压缩。

## 14. V6统一用户体验与支持判定

支持详稿共同消费DC02/10/11/12/16，不另建模型端“成功”账。资料充分性、模型能否解析、Host/许可、原能力资格、当前任务满足五类状态分别呈现；默认只显示影响用户选择的事项，内部attempt/fence/codec放诊断。

停止、等待资源、部分成果、未知效果和完成交付使用不同文案；完成基于实际载体/科学检查，百分比不能触发完成。变更时自动给事实/设计差异和已核重算范围，少问无关问题；学习候选按STYLE/DATA_MAPPING等角色显示来源、适用域、采用/撤销操作。

兼容与格式不因新行为扩大虚假支持范围：新Host/模型/字体/资源版本先走原矩阵资格，整个任务缺Pro/PS/Office必需条件则如实提示。工作台原48用户任务/24新人等门不缩，F01–06子行为加入对应原案例，人工确认、PS设计手工和技术异常时间仍分别测量。

## 15. V7普通用户流程的三个改进

自动适配展示“已证支持条件/待证缺口”；自动排版完整保留图例和必要说明，缺字体/裁剪不当作风格偏好；学习分“你明确保存的默认”和“系统已比较通过的优化”。用户可查看来源、本次覆盖、暂停或忘记，拒用即时生效与清理完成分开展示。

工作台消费同一支持/资格/事实/布局/控制/交付账；模型说完成、更新通知、点击更频繁或工期估算都不能生成产品成功。完整工期未知时展示影响截止的缺测项与实际资源，不输出假精确日期；原安装/领域/格式/零PS手工/用户门保留。

## 16. V8支持体验：先证明结果能被接收方使用

同一成果把可查看、可编辑、可复算及所需Host/字体/许可分别列清；本机能打开和JSON可解析不能等同完整交付。支持矩阵继续原全部动作格与输出承诺，新增用途/读集/复用/引用状态是精度维度，不拿“只需查看”免除原编辑门。

用户在一张任务卡选择用途与输出位置，系统自动完成参考风格迁移、科学检查和缺项恢复，展示未满足条件、复用原因与补齐进度。真实环境能力和当前授权另探测；未知显示待证。所有普通操作沿原Invokers与工作台，用户无需人工维护缓存/ICC/引用脚本，最终统一包仍在全部原功能门之后。

## 17. V9把“可用”与“等待”的原因呈现给普通用户

用户工作台从QualificationSetCertificate、AdmissionTicket及原Job状态投影：历史已验、目标域当前有效、当前环境可执行分别列；等待显示资源/许可/更新重资格/宿主在途/效果对账/输入不完整等准确原因。用户无需理解内部M/WI编号，领取/改稿仍自动完成。

环境或资源未知不虚报失败后自动切坏方法，也不虚报全部支持。系统给原质量内的具体路径：合法候选资源窗、已验等价分块/PPF、已批准模型替代、缺许可/软件/资料条件；改变科学域/用户批准必须由原流程明确决定。旧输出/用户编辑保留。

支持枚举、跨版本/格式/模型/行业资源包仍原全范围。单一桌面已验协调者是首实现边界；无多个Host的全局提交证明不宣传多Pro分布式资源协调。当前纯规划，真实容量/用户感受提升待同条件完整任务实测。

## 18. V10用户感受和自动化边界

用户输入业务目标和资料后，系统能更准确说明“统计的是多少实体/多少行”“缺哪些合法参与区域”“当前项目为什么没有沿用个人习惯”“哪张参考贡献哪种布局角色”“这个字段该填什么、为什么”。这些说明由typed决定与实际证据投影，不由模型自由写一个自信结论。

默认工作仍零PS手工设计：自动资料/方法检查、有限候选、真字体排版、PS/Office保存重开、科学与完整交付。必需条件冲突一次集中解决，可选习惯未知自动跳过并说明；不为每个可选选择反复打断用户。参考回退到完整已验模板必须满足当次原要求，否则保留差异/等待。

功能/输入输出/模型/跨版本/资源/学习/可访问与离线原支持矩阵完整保留。本轮细化这些原承诺的真实行为和错误说明，实际新手主动操作时间、误报、耗时及全链成功仍需24新手/48任务及原全部门同条件实测。

## 19. V11普通用户的完整体验

用户先给目标/范围/年份/用途，系统解释资料候选的适用与缺口；获准采用后重核当前支持。需要决策时展示“比较依据、并列/翻转条件、未验证范围”；需要成果时选择已支持语言与媒介，系统从同FactCell自动生成可编辑图文及阅读说明，用户不手工修PS或猜技术字段。

支持、费用和未知条件都投影到同一任务卡：候选资料非已验、方法可比非可替代、有限稳定非现实保证、阅读文件非查询文件。必要条件冲突集中问询，可选未知保留说明，根预览/修复预算及全功能门不重置。原模型/版本/资源/离线/辅助阅读/全部格式和零手工承诺完整保留。
