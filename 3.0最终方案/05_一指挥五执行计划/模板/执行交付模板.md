状态：TEMPLATE_ONLY。有效执行端交付状态只能为PASS CANDIDATE或明确受阻/待验，不得自签产品PASS或关闭验收记录。

## 1. 工单对应

填写当前唯一ACTIVE批次、工作包、owner、派单方、WI/J/PF、有效授权与权威inbox链接。记录实际读取的基线/payload/合同版本、时间和SHA256。若与派单不同，说明差异和裁定来源；未获处理不继续扩大效果。

## 2. 最终变更与成果

描述具体触发及最终行为、实际支持域、合同diff、消费者如何调用。列全候选文件/删除/改名、绝对D盘路径、长度/hash及E1集成所需信息；说明产品树没有多写者。每件实际产物与对应任务/输入绑定，不复用其他版本路径冒充当前结果。

补充当前 `milestoneId / parentWiId / scopeLevel / producerMilestoneRefs / consumerCaseRefs / acceptedScope / remainingFullScope / fullWiDependencyClosureSatisfied`。子切片证据绑定其payload和支持域；提交PASS CANDIDATE不预填接受。合同/mock、真实切片、完整WI三个级别分开，完整依赖未关闭时不能请求整项关闭。

## 4. 效果与资源清算

逐effect记录稳定key、intent、dispatch、观察、receipt、当前owner/fence、目标/文档ID、grant/批准。超时可能已经写完，未知不伪装未写；分别记录Host结束证据、计算lane归还与目标/空间/预算结算；未知效果依各资源策略隔离，不能把已结束lane永久锁住或把lane归还当零效果。取消后停止新业务并完成观察；剩余写者/进程/锁要实际复核，不只靠命令退出码。

## 5. 资格、影响与复用

给完整前后依赖闭包、当前有效资格新增/撤销/失效/恢复集合，去重后净数；Artifact/Render/Evidence/current effect四轴分别说明。依赖/参数/许可/Host/oracle改变需重新资格，不拿schema相同保持旧binary证据。声明具体覆盖门及还没验的全门；数量不能替代功能质量。

## 6. 成本与下一步

按唯一costKey分别报准备/实现/纯测试/Host/专业/E1/C0、失败返工、内部外部等待、冷/热、费用/磁盘和剩余乐观/通常/保守时长。未知为null；按净项摊销或逐attempt二选一避免双算。

列下一消费者、未完成/阻断及所需裁定，提交PASS CANDIDATE。交付不构成C0已接受；保持原全部范围和门，不把缺项偷偷改为后续自主学习。
