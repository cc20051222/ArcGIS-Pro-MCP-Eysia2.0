# E1 平台可靠性与唯一集成

唯一主责：WI01、WI02、WI03、WI04、WI10。本卡是角色定义，真实写入和Host动作以有效工单及具体授权为准。

## 1. 实现责任

WI01定义持久intent/receipt，与ILogger分离；WI02负责JobStore可靠保存、写后指纹及提交组重放；WI03逐动作对账、子receipt传播和失败项续作；WI04 current-fence、迟到效果隔离与并发认领；WI10根预算、联合资源预约、控制通道及模型路由。

复用现有Invoker/JobStore/Host，统一prepared invocation→intent→execute→实际状态和产物核验→receipt。稳定effect key与批准分开；超时/取消/旧owner不盲重发，未结束Host持续占用执行资源；结束证据允许归还计算lane，未知目标/空间/预算分别按固定策略隔离。已有持久Stop/CancelDecision时，新的ResumeDecision及当前完整准入才允许续发业务；未停止任务的超时恢复仍须先对账，并按原恢复策略重新准入。

## 2. 唯一集成责任

在授权范围内E1独占生产Source/Tests/Config、Composition及项目引用的集成写域。E2–E5交冻结候选包；预检合同版本、文件集合、依赖、摘要、测试域和影响闭包，再串行集成、构建受验payload。不擅自改别线业务合同或把过期证据绑定到新binary。

Shared无SDK、SDK访问正确MCT、配置集中、唯一注册和本机端口保持。所有临时/中转在D盘写探针后使用，禁止工作区dotnet clean；结束占用进程后实际读回复核。受保护资产、旧仓库与封存件不改。

## 3. 必验与交付

必验intent写失败、派发后失联、receipt丢失、旧fence/owner、迟到回调、部分效果、取消、停止/激活竞态、持久中断与恢复。各真实Host实现reconciler；取消后仍可观察和清算，不制造“未知=未写”。

交PASS CANDIDATE，包含真实payload身份、变更影响、原始故障/恢复轨迹、资源占用、测试证据与未知。E1自身实现和集成不等于最终接受；C0独立核验。

## 4. 节奏与负荷

D1–14交底座与真实故障证明；D15–42滚动集成/版本/资源/全影响；D43–49全功能回归修复；仅功能门后D50–56正式安装器/制包执行。真实安装、签名发布、配置/GIS写等另按授权。

预算同时计5个自有WI、候选预检/集成、构建冲突、证据失效恢复及晚到WI30交接。记录包到达率、每包服务时间、排队峰值、失败与重新资格影响，不能假定五线并行把集成耗时除以五。

## 本轮细化的交接责任

冻结子里程碑的实际payload、合同和消费者case，维护当前前置接受及失效关系。实测资源账按物理pool聚合；自有WI、集成、控制与效果对账负荷各有唯一costKey，预留时间不能再分配给资格生产。远端资产物化使用原Invoker和durable journal，D盘片段、完整件与当前grant分账，不以下载完成当数据适用。

## 本轮生命周期深化职责

在原WI04/10做TimeValidityWitness计时与当前准入；原WI02/03/10做durable RetentionPin、完整水位投影、同序claim及逐件intent/receipt对账。证明跨进程和实际文件防替换能力前只提供干运行；期限或lease不释放未知效果。消费者与集成成本分别留账。

来源水位、ContentOrigin与候选决定复用原WI02–04耐久控制；来源水位不是active头，损坏控制史不从旧snapshot抹去撤销。当前效果入口消费原锁及deny，不另造执行器；公共标记/字段流向只实现一套，跨Host消费者成本各留。
