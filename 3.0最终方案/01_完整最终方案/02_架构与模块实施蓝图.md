# ArcGIS Pro MCP 3.0 架构与模块实施蓝图

日期：2026年10月3日。本文规定完整产品的可实现路径、模块输入输出、故障处理和完成证据。服务、合同和方法名称是内部设计职责，实施时优先适配既有类型，不直接作为新公开MCP接口。全部新增行为仍为规划状态；源码、参数、真实运行和独立验收不能由本文推定。

## 1 宿主边界与唯一执行路径

ArcGIS Pro插件承担DockPane、对象选择、GIS宿主服务和SDK适配。Shared只保存合同、计划、策略、作业、模型提案、事实和资源逻辑，不引用ArcGIS SDK。SDK对象只在Compatibility及IArcGISHost内访问，涉及MCT的访问经QueuedTask.Run转换成稳定DTO；不能将SDK对象或活动图层句柄带入后台模型、持久任务或跨宿主缓存。

既有受控Python Bridge保留固定类型化操作，端口与来源集中配置；额外计算提供者通过已审查固定adapter接入同一准备与执行层。新增provider不等于允许用户运行任意脚本。Photoshop UXP peer执行固定命令，拥有文档和文件grant明确绑定；Office采用固定Report/Workbook/Presentation adapter，承诺原生编辑性分别检查。三类宿主共享任务与事实身份，不共享SDK对象，也不假设跨宿主事务。

所有入口汇入同一链：语言/表单/技能/更新/修复 → 类型化计划 → Preparation → 唯一Invoker → Host/provider → 独立观测与oracle → durable receipt。Composition.BuildRegistry为唯一工具注册，Configuration集中端口、路径、超时、预算和开关。自动化不会建立第二个拥有权限的执行器，也不开放新的任意Python、JS、Shell、SQL或6511旁路。

## 2 十二个内部服务及存储落点

| 服务边界 | 输入与输出 | 实施与存储责任 |
|---|---|---|
| SV01 DataBindingService | 当前资料、对象选择 → DatasetContract、InputSnapshot | Host转DTO；D盘拥有输入副本/元数据；采集窗口与限制不可丢 |
| SV02 AdequacyAndDecisionService | 业务目的、数据、方法规则 → AdequacyReport、DecisionRecord、关键问题 | 无SDK纯判断；方法/规则版本化；未知不猜 |
| SV03 PlanCompiler | 已采用决定、OutputContract → typed DAG、effects、planDigest | 不发宿主命令；冻结依赖和版本；复用既有validate_plan边界 |
| SV04 InvocationPreparation | 步骤、当前资格、批准、环境与资源 → PreparedInvocation或缺口 | 统一Validator/Invoker前段；规范值与原输入分别保存 |
| SV05 ExecutionJournalRepository | intent、dispatch、receipt → durable ack、重放状态 | 适配既有WorkflowJobStore；诊断日志和执行事实分开 |
| SV06 ResourceScheduler | 根预算、需求、容量、Host约束 → 原子reservation和有限队列 | Shared持久预约；宿主lane按实际资格；不靠进程数推容量 |
| SV07 ReconciliationService | 动作历史、当前宿主/文件观测 → 无效果、完成、部分、未知 | 每动作固定策略目录；无可靠策略就等待，不盲重试 |
| SV08 FactAndClaimService | 已验分析 → TypedFactCell、ClaimBinding、科学解释 | 内容oracle通过后产事实；D盘版本表和出处索引 |
| SV09 DesignAndRenderService | 同版事实、模板、参考 → DesignSpec、GIS素材、固定PS命令 | 确定性约束求解；真实字体/尺寸；精确与视觉输出分路 |
| SV10 PsExecutionServices | 固定命令、grant、拥有文档 → 宿主receipt与独立状态 | Gateway、全局写Queue、Ownership、FileGrant共用动作身份 |
| SV11 DeliveryService | 同版事实、设计、Office、CheckReport → candidate/active DeliveryRevision | 成员hash/内容/结构齐验；完整manifest耐久激活 |
| SV12 UpdateAndCompatibilityService | 数据/方法/环境差异 → ImpactPlan、兼容/迁移/停用 | 三类缓存键、完整依赖闭包、历史载体不就地破坏 |

初版以既有JSON/JSONL作业载体、版本化manifest和文件资产实现，不以新数据库集群、消息中间件、在线微调或多服务部署作为两个月前置。需要新依赖时登记实际用途、许可证、部署、维护和回退成本，再按有效授权引入。

任务状态区分DRAFT、PREFLIGHT、READY、QUEUED、RUNNING、VERIFYING、PREPARING_DELIVERY、DELIVERED，另有待决定、待对账、部分、失败、取消和被新版本替代。步骤成功既需VERIFIED又需RECORDED；效果另记NOT_STARTED、NONE_PROVEN、IN_FLIGHT、OBSERVED_UNVERIFIED、VERIFIED、PARTIAL、UNKNOWN。响应失败或取消不证明没有写入；真实效果通过但回执未耐久保存，进入RECORD_PENDING，不能把宿主动作重跑。

## 4 通用执行与恢复必须先建成

每动作经过十个闸门：读取精确版本依赖；规范类型与单位；计算全部条件effects；检查范围、路径、许可、方法和批准；联合预约根预算与资源；耐久intent成功；派发前复核当前输入/资格/批准/fence并记dispatch；观测效果后独立检查；耐久receipt；所有必要依赖和成员合格后激活完整交付。

稳定业务效果键绑定逻辑动作、输入、方法、规范参数、目标与effects。批准、policy、owner、fence、预算绑定当次执行锁。批准编号变更不能把已发生的同一业务效果当成新动作；传输requestId、随机invocationId不用于业务去重。旧owner迟到写出的效果仍需观测和隔离，拒绝其回执不是回滚效果。

持久事件优先包装既有JobStore：UTF-8、单调sequence、eventId、frame/group与完整commit标记。提交后才更新内存指纹；撕裂尾部、半组、重复、摘要损坏分别处理，不能统一当未执行。group commit必须完整耐久确认后才能放行动作。日志打印“persisted”不证明真落盘，Flush或原子rename也不能代替故障实测。

对账策略四类输出：可靠无效果只是可重新执行的必要条件；内容、归属、版本、oracle全一致则补回执；部分效果只在批准且可核的补全/补偿域继续；未知则保留并暂停受影响依赖。已有持久Stop/CancelDecision时，即使证明无效果也不能自动续发业务动作，必须先取得新的ResumeDecision、当次批准并复核完整准入、许可、输入、预算、资源和fence；只读对账与补记既有实际效果回执可继续。清未知锁、覆盖用户外部编辑、整段重发和把文件缺失当无效果都不允许。

## 5 二十模块逐项开发方法

### M01 能力目录

输入为可信来源快照、参数合同、逐项资格和当前环境，输出CapabilitySupportManifest及分层发现视图。目录采集保留规范操作ID、provider/binary、参数域、许可、效果、语义组、适用条件、失效水位和原证据引用。六账本从这些引用分别投影，前端和帮助不能另写“全部可用”数组。

开发步骤为采集可信全集并固定版本；归一旧新入口与别名；生成合同/搜索/表单；接资格和可用性投影；接新增/删除/变化影响。WI11–15、30负责主目录，E2牵头。目录不完整、未知许可或跨版本混域时标UNKNOWN/CONDITIONAL；数量按当前有效证书的去重成员，不保留失效旧总数。验收注入别名重复、同名异义、目录删改、binary同签名变化、UI状态滞后，证明发现与执行数量分别真实。

### M02 数据语义

输入为用户对象、表格、科学数据或服务记录；输出DatasetContract、InputSnapshot和采用的字段/实体映射。WI05–07由E3主责。对象绑定先解析稳定LayerRef/DatasetRef和完整selection，记录实际字段、CRS、轴序、单位、时间、几何、来源版本及读取隔离；资料抽取保留sheet/页/单元格和原字符串。

接着生成DatasetDNA候选，使用已验别名与明确单位转换，关键歧义集中确认；完整ReadSet记录所有影响阶段结果的输入，而非只记录主文件。实体键采用有类型的复合值序列，前导零不能被自动数值化，显示拼接名不作规范身份。验收覆盖同名图层、同数量不同selection、日期系统、错单位、缺CRS、OCR关键错值、分页漂移和输入过程中变化。不能获得所需一致窗口时创建获准拥有副本或等待。

### M03 数据治理

输入为冻结schema、记录、几何及采用RulePack，输出治理计划、新拥有库、字段/实体映射、拒绝项和QC报告。实现几何有效性、身份重复、字段/域/子类型/关系与规范覆盖，并明确数据库内建约束和应用QC的不同。E3提供语义，E2提供受控操作，E5业务规则，生产集成由E1。

治理先检测再计划，再按拥有副本执行和读回。连接合同声明一对一/一对多基数、未匹配、重复、null键和原粒度；新已验配方默认null键不匹配，原公开行为变化需裁定。两个实体金额相同不能用DISTINCT金额去重；连接扩大后的金额/人口不能重复汇总。验收注入重复复合键、域依赖、非法存量值、有损字段、脚注例外和缺适用条件。失败保留原件和问题记录，不删除难数据刷合格率。

### M04 任务编译

输入为IntentFrame、表单或SkillIR、当前决定和OutputContract；输出typed DAG、规范步骤、依赖、风险、planDigest和可行性。WI08–09、27由E3负责。先识别业务问题，再方法硬过滤，再固定数据/输出/变量和effects，最后估资源并生成计划；模型推荐名只形成候选。

DAG节点保存输入、方法、参数、资格、效果、检查和对账策略，修订有明确父版本和改变集合。@点选、框选、距离和时段组合按稳定对象及全集物化，不按最新活动地图推定。验收空输入、模糊指代、非法方法、循环依赖、缺必要成员、计划修改越界与旧context，确保无有效计划时dispatch为零；等待期间输入变化则重编新的revision。

### M05 执行策略

输入为规范参数、目标、计划、权限、许可和准入，输出可准备动作或具体拒绝报告。WI13/E2与WI01、10/E1合作。参数谓词决定原位修改、输出、侧车、中间件、地图状态、删除、外发和计费effects；派发前再次检查，不能只信静态“只读”标签。

实现A0提案、A1采用后执行、A2当前范围内有界选择/修复、A3专门限定持续更新策略。持续策略不复制旧批准；未知effects和未审来源隔离。旧run、compact和granular入口必须同一policy/准备/预算/恢复，不能某入口绕准入。验收路径逃逸、参数改变effects、许可撤销、过期批准、原件保护和远端曝光，拒绝有准确原因，符合任务的合法操作也应完成。

### M06 作业恢复

输入为PreparedInvocation、事件流、资源日历与实际观测，输出任务状态、进度、取消、对账和可续作检查点。WI01–04、10由E1负责。建立耐久journal和提交组重放、lease/fence、稳定逻辑动作；每操作配置ReconciliationStrategy；控制通道和后台学习分开优先级。

CPU/RAM/VRAM/磁盘、Pro/GP环境、同GDB、PS全局写和许可联合原子预约，不允许只占一部分资源导致死锁或过卖。Host结束与效果结算分别处理：证明Host结束可释放lane，但未知GDB/PSD或交付effects仍隔离。有限ready/WIP、预算和排空机制避免巨型队首阻塞及小任务长期插队。验收intent失败零派发、效果后receipt失败不重发、旧owner、晚取消、部分保存、lease超时未停止和重启复盘。

### M07 空间与网络

输入为方法合格的数据、空间查询、规范单位、网络/成本/时段与批准，输出几何结果、覆盖集合、统计与实际效果。实现原全部缓冲、叠加、测量、空间统计、网络等语义，E2提供逐项资格，E3方法/分母，E5业务oracle。操作优先走现Host服务，已审固定provider补缺仍经唯一Invoker。

方法卡锁平面/测地线、距离单位、容差、边界归属、真实路网与未知对象；网络许可和成本模式不足不能用直线缓冲假代。设施联合覆盖按稳定实体集合并集，人口分配另有明确模型。验收几何/面积守恒、重叠人口去重、断路与网络外未知、可达成本和时段变更；每操作真实正例、关键负例和独立内容oracle，不只查返回成功。

### M08 栅格与遥感

输入为多期栅格、科学立方、遥感资产、QA及已验方法，输出同格网结果、支持域、NoData/有效统计、变化与科学事实。实现CRS/轴序/变换、范围、格网锚点、snap、像元大小、重采样、mask、类别字典、时间/历法和单位锁。E2管操作资格，E3科学合同，E5领域链。

分类与连续值重采样不同；全NoData不生成数值零；空zone、非法zone和缺测另记。均值必须说明eligible集合，带权均值的value/weight使用同一集合、有限非负权重且和正；比例和汇总依人口/空间支持而定。合法PPF、分块/halo和全局统计固定配置必须证明整体等价，不默认每工具可切块。验收边缘、变锚点、全缺测、类别映射、面积与转移边际守恒、新期次和训练/参考独立性。

### M09 符号与标注

输入为已验FactTable、类别、StyleProfile和用途，输出渲染、图例、标注与科学色义映射。E4设计，E3语义，E2现GIS操作。先绑定类别/指标/单位和范围，确定跨图跨期同义，后做批量配色和标注；匹配图层集合先预览，不能模糊通配关错层。

定量色带、类别阈值和科学符号锁定；参考色彩只能在满足语义与可读域内使用。非颜色冗余编码、色觉和灰度检查补充而不修改原事实。验收漏图例、系列色义倒置、标签遮挡、父组/全局效果污染、临时图层改变和中文字号；改风格使渲染依赖失效，事实不被重新解释。

### M10 模板布局

输入为DesignSpec、真实文本/图例内容、36模板、用途合同和可选参考，输出布局候选、多图框、图册与页面规格。E4主责WI17、20，E5准备业务模板。模板不是静态截图，须定义语义槽、可变容量、网格、间距、字号区间、图框关系和必要说明。

布局先真实测字形/边界，再确定性枚举合法列/面板和约束，最后有限排序与改稿。图册页ID、index、extent、scale及系列颜色固定，支持100页完整性与续作。20改稿明确样式和分析变化的分界。验收长标题、密集图例、极端比例、缺字体、中文英文字形、多图框和漏/重复页；无可行方案不删除科学项，返回具体需要改变的用途条件。

### M11 素材交换

输入为GIS精确素材、画布/物理尺寸、地理框与来源，输出LayerBundle、配准与布局映射、视觉素材和独立矢量成果。E4主责，E2/Host提供实际布局导出。记录每层语义、坐标/像素关系、裁边、透明度、DPI、范围和内容摘要，避免各层导出时独立缩放漂移。

GIS精确层嵌入PS的同时保留可复核原素材，非均匀缩放、独立移动比例尺、裁掉必要边界和遮挡保护区禁止。透明裁边不改变地理框定位；等比缩放重新核比例与物理尺寸。验收控制点配准、图框/比例尺、层顺序、透明边、纹理影响和实际矢量结构，失败保留原素材，新版本修正交换Spec。

### M12 Photoshop连接

输入为实际Adobe/UXP身份、pairing、协议、支持摘要和批准范围，输出真实能力快照、session、DocumentOwnership和FileGrant。WI18由E4负责，E1接公共可靠性。先探真实PS/peer版本和API域，通道echo只记连接层；精确job-owned文档和文档/图层ID绑定，保存重开后重新绑定。

grant与持久token有效性读回检查，身份同名/同路径不足；凭据和token不进入项目包、日志或偏好索引。断线、busy、重启、旧peer、失效token时标能力缺口，进行实际效果对账。验收连到错误窗口、活动文档变化、重连同名文档、文件访问越界，确保必需PS未合格不能获得全链完成。

### M13 UXP固定动作
