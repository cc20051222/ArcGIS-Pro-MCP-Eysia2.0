# 主流项目对比与全面领先验收方案

编制日期：2026-10-02。适用版本：本项目 3.0 最终方案，完整继承 V11 的范围、原质量门与新增质量门。

本文供产品负责人、开发团队和独立验收者阅读。结论是：把广覆盖的 GP 入口、低门槛接入、地图上下文、可复用技能等成熟社区方法吸收进统一底座，再通过真实操作资格、专业方法判断、零 PS 手工设计、同源事实与跨软件恢复形成可验收的组合优势。全面领先是本项目的建设和验收目标；截至编制日，本轮未运行竞品或本项目的竞争测试，不能把方案目标写成已经取得的结果。

## 1 对照范围和证据身份

样本按与 ArcGIS Pro 桌面执行链的直接关联、公开可查资料和实现方式选择，包含 6 个公开仓库和 GeoAIChat 相邻产品。这里的“主流”表示用户关注的代表实现路径，不是市场份额或下载量排名。面向 Portal 的服务助手和只做文档检索的 MCP，不直接充当桌面完整任务的等价对照。

| 证据身份 | 可以说明什么 | 不能据此说明什么 |
|---|---|---|
| 公开宣称 | 作者公开了功能、数量、安装方式或速度 | 全部功能已通过我们独立的运行验收 |
| 静态核查 | 固定提交中的文档、代码结构与合同可以追溯 | 当前用户机器许可、版本和真实成果成立 |
| 真实运行 | 指定宿主和资料上得到实际效果并完成内容读回 | 未运行的其他操作、输入域和版本也成立 |
| 独立竞争验收 | 冻结条件、完整样本和预定指标下的比较结果 | 永久领先或对未来所有场景都更优 |

本轮公开仓库通过官方 GitHub 页面和 API 读取，固定提交及 README 哈希记入 [来源台账](sources.json)。GeoAIChat 的网页浏览工具访问失败，但 PowerShell 对官方页面、页面加载的 JavaScript 和版本 API 的只读 GET 成功；这是今日官方网站材料核查，并未安装插件或核验源码。其宣传“开源”，本轮仍未核实其自身源码仓库与许可证，不能直接当作可复制代码资产。[GeoAIChat 功能页](https://www.geoaichat.cn/features)、[公开版本 API](https://www.geoaichat.cn/api/packages/history)

## 3 数量领先采用两个独立完成门

工具入口数与能完成的业务范围关系很弱。一个通用 GP 入口可以覆盖大目录，许多命名 wrapper 也可能只是同一方法的别名。我们的优势必须同时体现在数量、实际可用条件和质量，不能用拆入口凑数。

| 台账 | 统计单位 | 本项目要求 |
|---|---|---|
| 对外 MCP 台账 | 当前实际注册且可发现的端点 | 公开原生、GP、Python 等分布，不当作算法数 |
| GP 资格台账 | 冻结 GP 分类下去重操作及选定运行见证 | 旧门 K_GP 与冻结对照操作集合覆盖独立通过 |
| 核心语义台账 | 核心 GIS、空间计算、转换与治理的独立方法能力 | 新门 K_sem 独立通过，同算法跨 provider 不重复 |
| 参数与支持域台账 | 参数族、版本、许可、输入类型、规模及环境 | 候选、完整合同、准入、运行、独立接受分开 |
| 产品功能台账 | PS、Office、学习、UI、安装、行业业务和模板 | 按各自完整行为验收，不混入核心语义分子 |

目标公式保持原方案要求：

- `K_GP = max(2100, ceil(1.10 × N_GP))`。
- `K_sem = max(3000, ceil(1.50 × N_sem))`。
- `N_GP` 与 `N_sem` 按各自同口径冻结，目前均 `NOT MEASURED`；1900+、约 1800 或约 2000 都不能填成精确实测值。
- 冻结对照 GP 集合覆盖要求 100%，可信系统目录发现要求 100%，完整参数合同编译要求至少 95%；剩余未完成合同的项不能算为可执行支持。全部发行门仍需逐项成立。

这两个门不能互相抵消。3000 个跨提供者核心语义不能替代对 Esri 对照操作的完整覆盖；把 PS、模板、模型提供者加入语义分子也不能通过核心数量门。更换输入格式、参数排列、线程数、模型版本、别名、wrapper、配方或同算法的另一实现，都不增加核心语义数。

### 3.1 如何在数量上真正超过同一 Esri 全集

同版本、同许可、同 Esri 全集存在相同目录上限。双方真实覆盖它时只会持平。新增数量要来自明确新增的方法能力：受审查的 GDAL/OGR、QGIS Processing provider、专业自有实现或可信第三方算法。每项先检查方法差异和等价关系，再检查许可与运行条件，最后取得真实输入、必要反例和独立内容检查；“换后端”本身不增加数量。

GDAL 文档提供算法 registry、参数元数据和 `Run` 机制，`Run` 标为 3.11 新增；QGIS `qgis_process` 提供 list/help/run 和 JSON 参数。它们支持降低适配重复劳动，不证明本机已安装、所有 provider 已可信或目录互不重复。[GDAL Algorithms API](https://gdal.org/en/stable/api/python/utilities.html)、[QGIS Processing Executor](https://docs.qgis.org/3.44/en/docs/user_manual/processing/standalone.html)

### 3.2 自动更新如何避免越用越不可靠

更新链为：只读环境探测 → 可信来源快照 → 差分分类 → 参数合同候选 → 科学方法与效果审查 → 首次运行资格 → 独立接受 → 分阶段激活 → 当前支持域重算 → 失败停用和回退。每次记录来源、版本、许可、contract、oracle、host 和依赖指纹。

新增工具发现可高度自动化；新类型、未知副作用、变化后的算法含义和困难 oracle 不能自动跳过。旧资格依赖变化时先失效，未知 codec 放入隔离区。用户可以看到“发现 多少、可编译 多少、当前可运行 多少、已独立接受 多少”，不把目录增长显示为全部已可用。

## 5 普通用户能够明显感受到的区别

### 5.1 通用入口先建好，用户只决定关键业务问题

用户选择资料、说明目的和成果，例如“规划汇报图册与报告”或“科研专题图和方法附件”。系统只读盘点并集中询问会改变结论的未知；任务卡展示对象、时间、方法、输出目录、预算和交付成员。确认后自动完成数据治理、分析、事实检查、设计、真实宿主执行、质量修正和保存重开。用户看到完成、待资料、待许可、待批准、失败对账、取消中等真实状态。

用户不必学习 GP 参数表和 PS 图层操作；必要业务判断、首次许可与效果批准仍明确记录，不能藏进“全自动”统计。用户修改标题、排版偏好或替换数据时，系统展示哪些任务会重跑，允许在新版本中更新，并保留外部修改原稿。

### 5.2 三个完整例子

| 场景 | 用户输入 | 自动行为 | 看得见的结果 |
|---|---|---|---|
| 规划汇报 | 规划资料、行政边界、指标表和用途 | 校验期次/单位/关联粒度；生成图册、PSD、报告和演示；逐项核对数字 | 一次任务中取得关联成果，图例、比例尺、指南针及来源完整 |
| 科研专题 | 栅格/矢量、方法要求、论文图规格 | 检查 NoData、网格/尺度、投影和适用前提；必要时开展固定模型敏感性分析 | 图、表、方法说明和不确定性一致，不能用美化掩盖无效样本 |
| 参考模仿与更新 | 授权参考图/数据、自己的新资料、偏好反馈 | 提取布局与语义结构；不把参考图数字当真值；跨资料重绑定并生成新版 | 有相似风格和自己的正确事实；偏好可解释、可遗忘，旧版本可追溯 |

第三条是支持参考学习与更新的实现验收链，顺序仍为先共用底座，再规划汇报和科研专题模板。普通用户日常 PS 手工设计目标为 0；不能把设计师暗中补图当作自动完成。

## 6 科学约束使智能化具有实际价值

数据搜索先生成候选，不因文件可下载就认定适用。必须检查 AOI 实际覆盖、资产期次、许可、像元质量、单位、空间支持和方法需要；分页未完成不等于没有数据。补缺操作走原统一执行链，读回后检查精确剩余缺口，不能把下载成功写成缺口关闭。

不同方法结果可进入诊断比较，但“可比较”“可替代”和“科学合格”分开。敏感性分析冻结模型、样本总体、方向、归一化与锚点；不能每个权重重新拟合归一化，把失败样本剔除后宣称更稳。有限网格结果不自动代表连续区间、概率或因果关系。

参考学习限定为许可内的版式、风格和数据映射候选。阅读/OCR/索引前检查用途权限；同字节不等于同授权。个人、项目、组织偏好按所有者、键和范围解决冲突，不能只用最后一次反馈覆盖专业约束。科学系数、保护色带和事实来源不作为普通用户审美偏好随意学习。

跨媒介展示保留量的种类：绝对温度和温差不同，比例、百分数和百分点不同。小非零值不能被格式化成没有提示的零。可访问输出核对角色身份、实际文字和字形、编辑性与阅读顺序；同文件合同不能在未经允许时偷偷拆成两份文件交付。

## 7 同条件竞争验收的具体做法

### 7.1 冻结四种比较集合

1. **共同任务集**：对照声明前提内的可比任务，固定资料、输出合同、宿主版本、许可、硬件、模型和预算。
2. **对照声明集**：按其宣称目录核查发现、合同、可运行和真实结果；未知保持未知，不能当失败。
3. **本项目完整集**：保留原 60 场景、36 模板/108 图、21 来源族动作格、原规则、用户与隐藏样本，保证新功能没有挤掉旧承诺。
4. **差异化集**：PS 全链、参考学习、同源 Office、因果更新和恢复等新合同。若对照无公开证据，可记录本项目行为通过；对照真实能力未测时不发表排他性比较结论。

资料来源、版权、训练/评测隔离、隐藏答案、失败与未知如何进入分母，在启动前冻结；禁止只比较成功输出交集。首次操作资格、变体回归、完整任务和性能测试各有账，不能把通过一层写成全层通过。

### 7.2 测量值和发布规则

| 测量 | 具体记录 | 领先结论的条件 |
|---|---|---|
| 覆盖 | GP 去重操作、核心语义、当前支持域、未完成项 | 两数量门及冻结对照覆盖通过；数量、质量身份同时公开 |
| 成功 | 原始分母、首次成功、有限修复成功、未成功原因 | 全部硬门满足，共同任务表现不低于最佳可比对照 |
| 科学质量 | 原始事实、oracle、几何/统计容差、方法前提 | 硬错误门一票否决；美观和速度不能补偿错误 |
| 用户成本 | 主动操作时间、等待、澄清次数、人工 PS 设计、费用 | 改善目标预先冻结，再由同条件测量证明 |
| 视觉质量 | 盲评、可读性、科学色带、字体与布局错误 | 专业质量与科学保护同时通过，不能只取相似度 |
| 恢复能力 | 回执丢失、进程崩溃、重启、冲突、权限与版本变化 | 正确识别实际效果，重复写入和错误覆盖门通过 |
| 可维护性 | 新工具 diff 到接受的耗时、资格失效率、回退时间 | 至少覆盖新增、参数变更、删除、升级和恢复全过程 |

本版不新增未经测量的“快 10 倍”或“成本下降 90%”保证。允许发布的措辞是“在冻结任务集和条件下，哪些指标达到目标、领先多少、哪些保持可比、哪些尚未验证”。不得将平均分掩盖某个核心维度退步，也不能把缺少证据包装成“永久领先”。

## 8 数量与质量目标对两个月工期的影响

60 个日历日目标包含 D1–D56 工程期与 D57–D60 应急缓冲；T0 是正式批准且六席、许可、真实宿主窗口、资料和验收资源到位的开工点，当前未指定。数量资格不能凭五个 AI 并行自动实现：宿主运行、困难 oracle、E1 串行集成和 C0 独立验收都可能成为瓶颈。

资格窗口 D15–D42 为四个完整周。若两门选定资格见证已证一对一重叠，`K_union = K_GP + K_sem − K_overlap`；已经合格且仍有效的同口径见证记 `Q_union`。最低净接受需求为 `ceil((K_union − Q_union)/4)` 项/完整周。并集是实际选定操作资格见证的并集，不能只按抽象语义相同推定可复用。

以下全为示例，未测得真实分母或速率：

| 示例条件 | GP 目标 | 语义目标 | 已证重叠假设 | 并集 | Q_union | 四周净接受需求 |
|---|---:|---:|---:|---:|---:|---:|
| N_GP=N_sem=1900 | 2100 | 3000 | 2100 | 3000 | 0 | 750/周 |
| 同分母但无重叠 | 2100 | 3000 | 0 | 5100 | 0 | 1275/周 |
| N_GP=N_sem=2200 | 2420 | 3300 | 2420 | 3300 | 0 | 825/周 |

D7/D14 用真实工作包校准，D28 以至少两个完整周净独立接受吞吐、剩余资源约束 DAG、全部 Host 和人工窗口判断 60 日条件。失败、退回和等待不能从成本或分母中剔除。容量不足时应增加资源、改良机制或更新真实预测，不削功能、不降质量、不把待验功能移到发行后冒充完成。

## 9 五线如何形成组合领先

| 席位 | 与竞争目标直接关联的责任 | 与其他线的关键交接 |
|---|---|---|
| C0 指挥与验收 | 冻结公平分母和预期答案，派单，独立核查，发布受证据约束的结论 | 接受执行端 PASS CANDIDATE，不代写产品实现 |
| E1 平台与唯一集成 | Invoker、JobStore、效果对账、Host 队列、统一发布树 | 把其他线的候选变成可运行全链；集成耗时计入工期 |
| E2 GP 与互操作 | 目录、codec、provider、逐项资格、版本/许可兼容与后期包迁移 | GP 不绕过 E1 Invoker；方法语义由 E3 共同审查 |
| E3 数据与方法 | Data/Fact 合同、科学 oracle、方法与敏感性、更新依赖闭包 | 向 E4 输出被检查的事实和保护约束 |
| E4 自动设计与交付 | GIS 制图、真实 Photoshop、Office、StyleDNA 与多媒介 | 接收 E3 事实，向 E5 提供可运行模板和成果检查 |
| E5 领域与体验 | 八领域、模板、工作台、评测资料、新用户体验 | 业务样本不由实施者自己签最终 PASS；C0 独立判定 |

六席是正式开发组织要求；本轮文档协作工具并不等于已启动六席产品开发。每条线可以在其拥有的分支/目录开展不同准备工作，但共同产品只经 E1 集成。实际资源和合同依赖仍决定哪些步骤能并行。

## 10 最终竞争定位

本项目要争取的优势是：核心功能数量有真实新增且去重，复杂方法有前提和证据，普通用户几乎不做软件操作，跨 GIS/Photoshop/Office 成果可信并可恢复，新能力会持续发现和接受，用户偏好与参考学习能够迁移且可撤销。这组行为覆盖了工具、工作流、科学、设计、交付、维护和使用体验。

维护优势的办法是长期保存同口径基准、失败学习和版本资格，使新版本可快速证明改进；任何团队都不能合理保证未来竞争者不进步。最终宣传必须随验收证据更新，而完整开发要求和质量门保持不变。
