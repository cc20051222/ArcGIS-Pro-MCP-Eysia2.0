# 开源经验吸收与实现映射

编制日期：2026-10-02。范围：把已经核实的社区实现思路吸收进 3.0 完整方案，降低重复开发和交接损耗，保留每操作资格、原功能与全部质量门。本文件是实现计划；本轮没有安装依赖、复制产品代码或开始生产派单。

## 1 采用原则和实现顺序

优先复用本项目已经存在且真实合格的合同与组件；借鉴成熟的目录、声明式适配、依赖指纹、执行恢复和最小交互；对宿主特有行为做真实小型原型。工具数量、测试数量和缓存命中率分别记账。选型以“在合法支持域内减少完整任务成本”为标准，不为了使用热门框架再增加一个运行服务。

阶段顺序为：合同与探测 → 八个关键原型 → 三条标准链 → GP 逐项资格与领域铺开 → 全部质量门 → 一键总入口与真实发行测试。每次社区借鉴都有合同、拥有者、支持域、故障边界和证据，避免只写“自动化”和“自学习”口号。

## 3 GP 目录和适配工厂

Esri ListTools 支持列举可见工具，GetParameterInfo 返回参数元数据；发现和参数说明不是运行许可或科学结果证明。GDAL 算法 API 和 QGIS Processing Executor 说明目录/元数据/结构化执行的复用路线。[Esri ListTools](https://doc.esri.com/en/arcgis-pro/latest/arcpy/functions/listtools.html)、[GetParameterInfo](https://doc.esri.com/en/arcgis-pro/latest/arcpy/functions/getparameterinfo.html)、[GDAL 算法 API](https://gdal.org/en/stable/api/python/utilities.html)、[QGIS CLI](https://docs.qgis.org/3.44/en/docs/user_manual/processing/standalone.html)

具体实现：

1. ProviderScanner 在只读探测中输出 canonical id、版本、toolbox、来源、别名和许可条件，不写 registry。
2. MetadataNormalizer 统一参数类型、输入输出、基数、可空、默认、依赖、互斥和值域，并保持缺失/null/default 身份。
3. CodecRegistry 复用标量、列表、字段、要素集、ValueTable、复合类型、栅格和输出路径编解码；新增类型只能产生候选。
4. EffectClassifier 识别产物写、地图状态写、属性修改、删除和外部发布；未知效果不自动批准。
5. SemanticReview 确定方法、适用域、输出与等价组；相同算法多 provider 只计一语义。
6. QualificationFactory 绑定拥有 fixture、首次真实正例、关键反例和独立 oracle，逐操作生成资格回执。
7. Composition 仍是唯一对外注册入口；PublicCatalog 同时显示声明、可编译、当前准入、真实运行和独立接受的数量。

失效传播覆盖 provider/host/许可/参数/方法/oracle/数据依赖，不只比较名字。全目录运行要预算、宿主窗口和逐项接受容量，不能用批量生成 wrapper 代替它。

## 4 从 QGIS 测试模式建设资格流水线

QGIS 官方 Processing 测试使用算法、参数、输入和预期结果的结构化定义，并支持几何/字段比较与容差；历史记录能生成测试脚手架。我们借鉴结构，不把由被测实现生成的 expected 当独立科学真值。[QGIS Processing 测试](https://docs.qgis.org/3.44/en/docs/developers_guide/processingtesting.html)

每个 QualificationWorkPack 包含：操作身份、合同版本、支持域、输入 manifest、独立预期、容差依据、效果清单、必要正反例、Host/许可、运行预算和回执 schema。fixture 构建、运行器、oracle、报告器可以使用工厂减少手工；算法首次真值仍逐项独立校对。

难操作由小型手算、独立实现、受审科学规则或有适用前提的变形关系建立 oracle。参数族与 t-way 用例补充变体覆盖，不能取代原强制场景；没有独立预期的操作不能晋升独立接受。家族共享可以共享解析与准备，不能共享一个结果就验收所有算法。

批提交减少 C0 重复查 schema/路径/证据索引的时间，但 C0 仍核查每操作的必要见证和科学依据。吞吐只统计当前有效净接受的并集，不统计生成文件数、启动次数、退回项或重复资格。

## 5 从 DVC 和 Snakemake 建立依赖感知复用

DVC run-cache 将执行历史与输入、参数和 stage 关联；Snakemake 的跨工作流缓存通过步骤、参数、软件栈及原始输入形成依赖指纹。这提供可复用机制，不自动捕获未声明的 CRS、字体、ICC、模型和宿主状态。[DVC run-cache](https://doc.dvc.org/user-guide/pipelines/run-cache)、[Snakemake 缓存](https://snakemake.readthedocs.io/en/stable/executing/caching.html)

本项目按三条轴分别判断：

| 轴 | 判断键和条件 | 允许的复用 |
|---|---|---|
| 产物轴 | 完整 ReadSet、参数、方法、代码、模型权重、配置、时间/CRS/轴顺序/变换、字体/ICC 等 | 当前相同输入与实现下的拥有产物 |
| 证据轴 | 产物身份、oracle、支持域、Host、许可与策略版本 | 仍有效的独立证据；仅独立 oracle 规则变更可对不变产物重新验算 |
| 当前效果轴 | 目标状态、会话代际、拥有者、授权范围和实际读回 | 证明已发生且当前成立的效果；缓存文件不证明当前地图/PS 状态 |

授权不混入稳定 EffectKey，也不因 EffectKey 命中而绕过当前批准。全输入读集必须完整，有水位与依赖全集；仅“文件时间没变”不足以复用。外部 GIS 资料、用户 PSD/aprx 不作为缓存工具默认可清理输出。

样式变化只复用已合格 GIS 素材，在新拥有目录重新生成图与 Office；事实、单位、方法、输入或视觉科学规则变化则重跑完整受影响闭包。不能把影响计算范围的规则变动当作仅重验报告。

## 6 从 Temporal 学习可恢复执行

Temporal 官方说明活动可能执行多次或部分执行，建议幂等；活动回执未到达时会发生重试。我们借鉴“执行状态与外部效果分离”，不在两个月计划中默认新增 Temporal 服务。[Temporal 活动定义](https://docs.temporal.io/activity-definition)

统一链为 intent → execute → artifact/state verification → receipt。执行前持久化目标、输入与效果键，资源原子预留后取得 Host 排队权；执行后记录效果结算和宿主占用结算两条轴。超时、断连和取消不能直接记为无效果。

关键恢复路径：

- GIS 已产生数据但回执丢失：按预定身份读回内容；成立则补回执，冲突则隔离，不盲再写。
- PS 多动作部分失败：逐动作和文档代际读回，保留实际状态，再在拥有副本内恢复。
- 旧 writer 未退出：新 writer 不抢同一写资源；先证明宿主 writer 已停止，再释放预留。
- 取消已受理：界面显示取消中，实际效果对账和宿主退出之后才完成结算。
- 用户改了原稿：保留原稿，在新 revision 生成，不宣称自动无损合并。

Task 超时、资源等待、外部确认、专业人工和宿主运行时间都进入工期与费用账。快恢复不能靠掩盖部分失败实现。

## 7 资源准入借鉴 Prefect 和工作流引擎

Prefect 文档把缓存、结果持久化和锁分开，并说明不同缓存隔离级别；这启发我们分离结果复用与资源占用。框架的缓存事务不让 GIS/PSD 外部副作用自动原子化。[Prefect caching](https://docs.prefect.io/v3/concepts/caching)

实现为轻量联合准入器：一次性核查并预留预算、CPU/RAM/磁盘、Host/MCT/PS modal、目录与目标资源；失败则不持有一半资源等待另一半。队列有年龄、截止期、支持域和优先级，公平保证限定于可行任务及已冻结环境前提。不可行任务显示条件缺口，不让它永久堵住所有队列。

资格批运行与业务任务共享同一资源账。E2 高并发会侵占 E4 的 PS/GIS 测试窗或 C0 复核窗，排程必须显式协调。五个执行端是五种职责，不是五个可以同时写同一个 Pro/PS 的线程。

## 8 合同投影借鉴 Roslyn 的增量设计

Roslyn 官方 cookbook 强调增量流水线传递可值比较的状态，相同状态可避免后续重复生成。我们只借鉴可比较 IR 和定向投影机制，不预设必须添加新 generator 工具链。[Roslyn Incremental Generators Cookbook](https://raw.githubusercontent.com/dotnet/roslyn/main/docs/features/incremental-generators.cookbook.md)

一份 canonical contract 投影为：MCP schema、运行参数检查、UI 表单、文档支持表、回执字段和评测脚手架。投影 manifest 保存输入哈希、投影器版本和输出哈希，发生偏差时拒绝发布。真正的 expected 对独立 oracle 保持独立，不能从相同合同实现生成自我验证答案。

跨语言适配检查字符串/数值类型、数学整数、缺失/null/default、数组基数、额外字段和动态依赖。`10.0` 如合同定义为数学整数可以成立，但不允许为了“方便”隐式把字符串转成数值。UI 限制不能比运行限制更宽，UI 截断也不能悄悄改变业务参数。

## 9 自动制图与 Photoshop 采用真实宿主合同

Adobe 官方规定插件修改 Photoshop 状态需 modal scope，且同一时刻只有一个插件进入 `executeAsModal`；部分超时选项有版本条件。我们使用固定、受审的 descriptor 和真实读回，不将 batch 当作跨软件原子事务。[Adobe executeAsModal](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/media/executeasmodal)

DesignSpec 由用途、事实、尺寸、内容、语义角色、StyleDNA 与字体覆盖生成。LayoutSolver 先保护地图几何、图例、科学色带和事实，再安排装饰和标题；RenderBudget 限定候选与修正次数。字体、DPI、ICC、文本区域、图层身份、保存与重开都实际核验。

参考图只提供版式结构、样式和约束候选。科学事实来自用户自身合格资料。用户可以要求模仿参考风格，但不能自动沿用参考的数值、分母、CRS、时间或未知版权素材。普通用户不用 PS 手工设计；专业适用判断、首次许可和输出批准不伪装为机器自动判断。

零手工设计通过真实 36 模板/108 图、首次 ≥98 图通过、有限修复、PSD 和各导出成员重开验证，而非仅保存一个 PNG。相同图还要按 Office、PDF、印刷等用途检查字体字形、事实、科学颜色、编辑性与可访问阅读顺序。

## 10 自学习与持续创新的闭环

| 创新 | 具体数据与处理 | 自动化范围 | 晋升条件 |
|---|---|---|---|
| J01 可信能力更新 | 可信快照、差分、合同与依赖身份 | 探测/候选/部分回归高度自动化 | 效果、方法和资格满足当前支持域 |
| J02 逐项资格工厂 | 工作包、拥有 fixture、独立 oracle、运行回执 | 准备和结构检查批量化 | 每操作必要真实证据独立接受 |
| J03 语义能力图谱 | 方法前提、输入域、输出量、等价组 | 合格集合内检索、解释和替代建议 | 等价/非等价黄金与正确拒绝 |
| J04 StyleDNA | 授权成图、语义版式与约束 IR | 参考提取、候选设计和跨资料迁移 | 自身事实保持，授权范围成立 |
| J05 DatasetDNA | 字段、编码、单位、日期、CRS、粒度映射 | 映射候选及漂移检测 | 支持域、来源、反例和人工接受记录 |
| J06 偏好记忆 | 接受/拒绝反馈、所有者、键、作用域 | 可解释偏好建议与可撤销采用 | 冲突、遗忘、导出和无泄漏 |
| J07 经验回放 | 成功轨迹、失败最小例与版本 | 拥有数据上的重放和问题检索 | 不同合格数据回放、原失败记录保留 |
| J08 有界补缺与方案 | Need/Gap、成本、方法与支持域 | 生成补缺或方案候选 | 用户批准后原 Invoker 执行、精确残余读回 |
| J09 科学约束设计 | FactTable、保护区、布局与质量规则 | 多成果渲染和有限修正 | 专业科学与视觉门共同通过 |
| J10 因果更新 | 完整依赖图、输入/实现/规则版本 | 精确受影响闭包、合格素材复用 | 无漏更新、事实/证据/效果分别核查 |
| J11 声明式技能编译 | 有参数的 workflow IR 和预条件 | 录制转候选技能、重绑定和回放 | 无 arbitrary code，错资料/旧方法正确拒绝 |

不能通过“让模型记住更多”获得永久领先。实际闭环是：用户反馈和失败形成候选 → 适用/权限审查 → 两份不同资料重放 → 独立接受 → 有界采用 → 新输入漂移检测 → 停用/遗忘/回退。科学权重和方法前提不从审美偏好自动修改。

## 11 不直接照搬的做法

| 做法 | 本项目处理 | 原因 |
|---|---|---|
| arbitrary Python、shell、自由 SQL 逃生通道 | 保留受控 GP 与固定适配入口 | 当前架构、安全和可验收效果边界不允许旁路 |
| 每任务冷启动 ArcPy | 先测冷/热时延、锁隔离和故障恢复再选生命周期 | 更多进程不一定让真实任务更快 |
| 家族抽检即全量工具通过 | 只共享脚手架和代表性补充测试 | 每操作方法和科学结果仍独立 |
| 当前名字存在即旧资格有效 | 完整依赖 fingerprint 与支持域重算 | 参数、版本、许可和方法可改变 |
| 框架“恰好一次”即外部写一次 | 单独效果对账和 writer 退出证明 | 回执状态不保证外部操作未重发 |
| 默认用户目录缓存、/tmp 或公网示例服务 | 项目 D 盘拥有目录与 loopback 配置 | 继承 D 盘、统一配置和本机服务规则 |
| 共享模板、provider 目录直接合计算法数 | 等价组审查与分账 | 不同封装不等于不同科学能力 |
| 下载成功、OCR 相似或文件存在即完成 | 内容/方法/科学/可编辑/支持域核验 | 成果可用与形式生成是不同证据 |
| GPL/AGPL 代码独立进程就当许可问题消失 | 固定版本逐文件/依赖审查，现阶段借设计不复制 | 进程边界不能替代分发与授权事实 |

## 12 效率收益如何落到真实工期

目标收益来自：合同一次维护、多处投影；codec 与 fixture 准备共享；Host 生命周期减少重复初始化；增量依赖避免无关重跑；资格批次减少 C0 结构复核；拥有路径和效果对账减少返工；五线提前对合同，E1 只集成符合接口的候选。

每项建立优化前/后的相同工作包测量，包含准备、真实运行、oracle、退回、集成、独立验收及等待。报告净接受/周、完整任务延迟、实际费用和缺陷，不使用代码行/文件数/模型自评代替产能。原科学、用户、图像、格式、隐藏和发行门分母全部保留。

60 日依赖实测容量成立。D7/D14 测原型和工件成本；D28 复算两个完整周净吞吐与剩余资源约束；D49 完整功能门；通过后 D50–D56 制作和验证统一一键安装包；D57–D60 为应急缓冲。WI30 的兼容迁移/残余实现与 E1 集成都算开发成本，不能只计作安装检查。更具体的资源表和计算由本包工期提效、五线执行文档维护。
