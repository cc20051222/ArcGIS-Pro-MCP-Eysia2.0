前置：已按《安装教程》装好并看到 tools/list = 239 与 ping = pong。 版本 1.0.2 ｜ 生产工具 239 ｜ 适用 ArcGIS Pro 3.0–3.5（3.5 已实测；3.0–3.4 编译期兼容·未验证） ｜ 端点 http://127.0.0.1:6520/mcp

1. 它是怎么工作的（一句话）

你的 AI 客户端  ⇄  (本机 6520 端口的 MCP 服务)  ⇄  ArcGIS Pro（正在打开你的工程）
  • 服务跑在本机，只监听 127.0.0.1，不对外暴露，不需要公网。
  • 你能用的能力 = ArcGIS Pro 当前打开的工程/地图/图层/数据，加上它跑的地理处理工具。
  • 因此：Pro 必须先打开工程，并在 MCP 选项卡点 Start；否则客户端调用会失败。

2. 每次使用前的 3 件事

# 动作 判断成功的标志
1 打开 ArcGIS Pro，并打开你要处理的工程 有一个活动地图视图（有视图才能做"当前地图"类操作）
2 Pro → MCP 选项卡 → Start 一键窗口诊断显示 6520 监听
3 你的 AI 客户端开新会话 工具列表里有 239 个工具

提示：MCP 服务随 Pro 的 Start 起、随 Pro 关闭停；退出 Pro 后客户端自然就连不上了。

3. 连接验证（逐个客户端确认"真的连上了"）

安装成功 ≠ 客户端连上。只有各客户端自己发起会话并成功调用工具，才算连接级验证通过。 下面按"先通用、后分客户端"的顺序做，每步都记录结果（通过就勾，不通过就如实记失败原因）。

3.1 通用前置（每次都一样）

⚠️ 顺序很重要（实测踩到的坑）

必须先启动 ArcGIS Pro 并点 Start，再打开/新建客户端会话。 客户端的工具列表是在会话建立时确定的：如果会话是在服务未启动时建立的，里面根本看不到 ArcGIS 工具 —— 即使配置文件完全正确、6520 随后已监听也一样（旧会话不会动态补上）。 补救：让 Pro 处于 Start 状态，然后关掉客户端重开（或新建会话）。

  1. ArcGIS Pro 已打开工程 → MCP 选项卡 → Start（6520 开始监听）
  2. 一键窗口点「诊断」，确认 HTTP 层两项：tools/list = 239 且 ping = pong
  3. 客户端关闭后重开（或新建会话）—— 旧会话不会加载新工具

3.2 HTTP 层独立复核（不依赖任何 AI 客户端）

# 只读验证包与载荷身份
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify-one-click-package.ps1 -RootPath . -Json

# 直接探测本机 MCP 端点（等待 6520 → 工具清单 → 代表调用）
python clean_probe.py --expect 239 --wait 300

期望：tools_list.count = 239、duplicates = 0、代表性调用 isError = false。

3.3 各客户端自身连接（逐项勾选）

客户端 配置位置 验证动作 通过标准
WorkBuddy %USERPROFILE%\.workbuddy\mcp.json（引用 arcgis-pro-mcp） 重开会话 → 让它列出可用工具 → 调 ping 工具清单含 arcgis 工具、ping 返回 pong
Codex 项目内 .codex\config.toml（或 %USERPROFILE%\.codex\config.toml） 用向导写入：CONFIGURE-CLIENT.cmd codex "<项目目录>" → 重开会话 会话中可见工具、ping 成功

3.4 连接失败对照表

现象 最常见原因 处理
客户端里看不到任何工具 ①会话建立时服务还没起（顺序错了）②会话是旧的 / 客户端没重启 先让 Pro 处于 Start，再关闭客户端重开（或新建会话）
全部工具都调用失败 Pro 关了（服务随之停止） 重新打开 Pro → MCP 选项卡 → Start
报端点不可达 6520 没监听 上一步做 Start；确认没有被防火墙/安全软件拦
PORT_OPEN_NOT_MCP 6520 被别的程序占用 关闭占用者后重启 Start；端口开着≠连上了
工具数少于 239 连到了旧版本服务 确认只装了本插件一个版本；重装后重开客户端
写操作报错 参数/图层名/输出已存在 先让它只读报告现状（见 §6 注意事项）

4. 怎么跟它说话（示例提示词）

直接用自然语言即可（中文/英文都行），让它调用工具、把结果讲给你听：

你想做什么 可以这样说
了解工程 "列出当前工程的路径、版本和许可信息"
看地图内容 "列出当前地图里的所有图层，以及每个图层的要素数量"
查字段 "列出 L_Points 的字段、别名的类型"
按条件选要素 "在 L_Points 里选出 POP 大于 10000 的要素，并告诉我选了多少个"
改别名字段 "把 L_Points 的 NAME 字段别名改成 名称"（写操作，见 §6）
空间分析 "对 L_Points 做 500 米缓冲区"
制图出图 "新建一个布局，加标题、图例、指北针、比例尺，然后导出 PDF 到 D:\out"
排障 "调用 ping 和 python_bridge_ping，告诉我是否都正常"

写清楚三件事：数据在哪（图层名/路径）、要什么参数、结果放哪。AI 客户端会把这些翻译成工具调用。

名称以客户端里看到的为准（共 239 个，无重复）。工具数变化会在版本的 release-manifest 中登记。

⑨ 生态对齐新增（13，D-061） save_project、create_map、set_workspace、get_workspace、list_rasters、list_tables、 get_unique_values、get_layer_features、export_layout_jpg、export_layout_tif、export_layout_svg、export_layout_eps、 repair_geometry

  • get_layer_features = query_attributes 的行预览预设档（limit 默认 10 / 上限 100，返回 preset=row-preview）——同一数据源、同一实现，显著披露。

  • repair_geometry 为就地破坏性操作，必须显式 confirm=true（缺省拒绝）。

⑪ 受控 GP 与信任层（D-062 新增，6） run_geoprocessing（白名单（D-062 起 51 件；★ D-066 起 53 件）受控 GP 通用调用：破坏性 confirm + 双向守卫 + OUTPUT_EXISTS + 审计落盘）、 list_geoprocessing_tools、describe_geoprocessing_tool、get_messages、check_extension、get_audit_log

  • run_geoprocessing 只执行白名单内工具（白名单外一律拒绝，禁止绕过）；v1 不提供覆写语义（输出已存在 ⇒ 拒绝）。
  • 编辑栈三件套改完必须 save_edits 才落盘，discard_edits 可整体回滚——先在副本上演练。

⑭ 图层管理（D-063 新增，10） set_layer_transparency、set_layer_scale_range、create_group_layer、set_basemap、get_broken_layers、 repair_layer_source、add_join、remove_join、rename_layer、duplicate_layer

6. 使用注意事项（很重要）

  1. 写操作先备份：add_field / alter_field / calculate_field / delete_dataset / rename_dataset 会真实修改你的数据。动手前先复制一份数据集，或在工程里用副本试。
  2. GP 输出会落盘：缓冲区、裁剪、合并等会产生新数据，请明确告诉它输出路径（例如 D:\out\xxx.gdb）， 不要让它写进系统盘或你的原始数据目录。
  3. 先只读后写：让它先用只读工具报告现状（图层、字段、要素数、坐标系），你确认无误再执行写操作。
  4. 需要活动视图：get_current_map、get_layers 这类"当前地图"操作在没有打开地图视图时不会成功 —— 先在 Pro 里打开地图。
  5. 中文、空格、长路径都支持；路径里有空格请用引号。
  6. 长任务：大表/大体量栅格（例如十几万行、上千兆栅格）耗时会明显变长，客户端可能显示等待，不要中途关 Pro。
  7. 错误码：报错一般带错误码，常见的有 LAYER_NOT_FOUND（图层名写错）、INVALID_ARGUMENT（参数不合法）、OUTPUT_EXISTS（输出已存在）、 PATH_ESCAPE_REJECTED（路径越界被安全策略拒绝）、ARCGIS_PRO_RUNNING（有写事务时 Pro 在运行）。
  8. 不要在 Pro 里手工改同一个图层的同时让 AI 去改它（可能冲突）；改完一处再做下一处。

"按顺序调用：get_project_info、get_current_map、get_layers、python_bridge_ping，逐项告诉我结果是否正常。"

建议分步执行（先分析 → 确认结果 → 再出图），每一步都让它回报结果。
